# NoSQL をはじめよう

この章では、表以外の形でデータを置く **NoSQL** を学びます。  
例は主に **Redis**（キーバリューストア）で示します。製品はほかにもありますが、現場で最初に触ることが多い「鍵で素早く取る」感覚を、Redis で手を動かして押さえます。

## この章で分かること

- NoSQL が向く課題と、RDB との役割の違い
- キーバリュー、ドキュメントなど、よく出る種類の地図
- Redis への接続と、文字列・ハッシュ・リスト・セット・ソート済みセット
- TTL（有効期限）と、キャッシュとしての使い方
- 注文のような「正」をどこに置くかの判断

## こんな場面で効く

同じ商品ページを開くたびに、中身はほとんど変わっていないのに、毎回 PostgreSQL へ同じ `SELECT` が飛ぶ。  
アプリサーバを増やしたら、片方でログインした利用者が、もう片方では未ログインに見える。  
週間の人気商品を出すたびに、注文表を全件集計している。

どれも「保存できていない」わけではありません。  
**取り方** と **寿命** が、注文の表とは違うのです。  
NoSQL、とくに Redis は、鍵で素早く読み書きし、不要になったら捨てる、という置き方に向きます。

:::tip[この章のゴール]

セッションやカウンター、ランキング、短い寿命のキャッシュを Redis で扱い、注文のような業務データは RDB に残す、という役割分担を説明できる状態を目指します。

:::
