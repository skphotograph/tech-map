# キーと文字列

Redis では、値より先に **キーの付け方** が設計になります。  
このページでは文字列型と、よく使うカウンター、上書きを防ぐ書き方を扱います。

## このページで分かること

- キー名の付け方（プレフィックス、区切り）
- 文字列の `SET` / `GET` / `EXISTS`
- `INCR` による、欠けない加算と、`SET NX` による「無ければ書く」

## キーには名前空間を付ける

キーはただの文字列です。  
表名もスキーマもないので、**自分で区切って衝突を避けます**。

この章では次の形を使います。

```text
shop:session:abc123
shop:user:10:profile
shop:product:1001:views
```

| 部分           | 役割                         |
| -------------- | ---------------------------- |
| `shop`         | アプリや用途のプレフィックス |
| `session` など | データの種類                 |
| `abc123` など  | 個体を指す ID                |

現場では `:` で区切ることが多いです。  
スペースや、毎回違う区切り文字を混ぜると、あとから一覧も削除も苦しくなります。

:::tip[キーは先に決める]

「値を入れてから名前を考える」と、同じ意味のキーが何種類も生まれます。  
種類ごとにパターンを一つ決めてから書き始めます。

:::

## 文字列にセッションを置く

ログイン中の「このトークンはどの利用者か」は、鍵が分かれば足りるデータの典型です。

```text
SET shop:session:abc123 10
GET shop:session:abc123
```

成功時:

```text
OK
"10"
```

値は利用者 ID の `10` です。  
セッション ID が鍵、中身が利用者、という向きにすると、リクエストのたびに「この鍵はあるか」で判定できます。

あるかどうかだけ見るなら `EXISTS` です。

```text
EXISTS shop:session:abc123
```

```text
(integer) 1
```

`1` は存在する、`0` は存在しません。

同じキーへもう一度 `SET` すると、**上書き** されます。  
RDB の `UPDATE` を書いたつもりがなくても、同じ鍵なら新しい値に置き換わります。

## INCR で数える

ページの表示回数のように、「今の値を読んで、足して、書き戻す」をアプリでやると、同時に二つの処理が同じ数を読む事故が起きます。  
Redis の `INCR` は、**サーバ側で 1 を足して、足したあとの値を返す** ので、その隙間が開きません。

```text
INCR shop:product:1001:views
```

初めてなら:

```text
(integer) 1
```

もう一度打つと `2` になります。  
`INCRBY` で足す量を指定できます。

```text
INCRBY shop:product:1001:views 5
```

文字列に数字以外が入っているキーへ `INCR` すると、エラーになります。  
カウンター用のキーは、カウンター以外を入れない、と決めておくと安全です。

## 無ければ書く（NX）

クーポンコードのように、「初めてのときだけ作りたい」ときは `NX` を付けます。  
`NX` は Not eXists（まだ無いときだけ）です。

```text
SET shop:coupon:WELCOME used NX
```

成功時:

```text
OK
```

同じコマンドをもう一度打つと、すでにキーがあるので書き込まれません。

```text
(nil)
```

`(nil)` は「書けなかった」です。  
上書き成功の `OK` と見分けると、二重発行を防げます。

<details>
<summary>XX は「あるときだけ」</summary>

`SET ... XX` は、キーが既にあるときだけ上書きします。  
「更新はするが、新規作成はしない」という向きです。  
このページでは、現場で先に出やすい `NX` を押さえておけば十分です。

</details>

## よくあるつまずき

- `user:10` と `shop:user:10:profile` が混在し、同じ利用者なのにキーがバラバラになる
- `INCR` するキーに JSON を `SET` してしまい、加算できなくなる
- `SET` の上書きに気づかず、セッションが別利用者の ID に入れ替わる

## まとめ

- キーはプレフィックスと種類と ID を、決めた区切りでつなぐ
- 文字列は `SET` / `GET` が基本で、同じキーは上書きされる
- `INCR` はサーバ側で足す。`NX` は「無ければ書く」
