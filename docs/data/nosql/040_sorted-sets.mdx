# ソート済みセット

「この週、どの商品がよく見られたか」を出すたびに注文表を全件集計すると、画面のたびに負荷が乗ります。  
**ソート済みセット**（Sorted Set）は、メンバーにスコア（点数）を付け、点数順で取り出せます。

## このページで分かること

- ソート済みセットのメンバーとスコア
- `ZADD` / `ZINCRBY` / `ZREVRANGE`
- ランキング用途での読み方

## メンバーとスコア

一つのキーの中に、**メンバー**（商品 ID など）と **スコア**（回数や点数）の組を持ちます。  
セットと同じくメンバーは重複しません。同じメンバーをもう一度入れると、スコアが更新されます。

週間の閲覧ランキングなら、次のように足します。

```text
ZADD shop:ranking:weekly 1 1001
```

成功時（新しいメンバーなら）:

```text
(integer) 1
```

見られるたびに 1 を足すなら `ZINCRBY` です。

```text
ZINCRBY shop:ranking:weekly 1 1001
ZINCRBY shop:ranking:weekly 1 1003
ZINCRBY shop:ranking:weekly 1 1001
```

例（最後の `1001` への加算）:

```text
"3"
```

`1001` のスコアが `3`、`1003` が `1` になった状態です。  
`ZINCRBY` の戻り値は、足したあとのスコアです。

:::tip[スコアは「並びの根拠」]

メンバーが「何を数えるか」、スコアが「何順に出すか」です。  
閲覧回数でも売上でも、**一つの数字で並べたい** ときに向きます。

:::

## 上位から取る

高いスコアが先頭に来る取り方は `ZREVRANGE` です。  
`REV` は逆順（大きい方が先）です。

```text
ZREVRANGE shop:ranking:weekly 0 9 WITHSCORES
```

例:

```text
1) "1001"
2) "3"
3) "1003"
4) "1"
```

`0` から `9` は、0 始まりで 10 件です。  
`WITHSCORES` を付けると、メンバーの次にスコアが交互に出ます。

特定メンバーの点数だけ見るなら `ZSCORE` です。

```text
ZSCORE shop:ranking:weekly 1001
```

```text
"3"
```

無いメンバーなら `(nil)` です。

<details>
<summary>小さい方が先のとき</summary>

所要時間や順位そのもの（1 が最上位）のように、小さいスコアを先に出したいときは `ZRANGE` を使います。  
このページの人気ランキングは「点数が高い方が上」なので `ZREVRANGE` です。

</details>

## 表の集計との違い

PostgreSQL なら、閲覧ログを溜めて `GROUP BY` と `ORDER BY` で上位を出せます。  
正の履歴が表にあるなら、その方法は間違っていません。

ソート済みセットが効くのは、**画面のたびに集計し直したくない** ときです。  
閲覧のたびに `ZINCRBY` し、表示は `ZREVRANGE` だけ、という形にすると、読み取りが鍵一つで済みます。

ただしスコアは Redis 上の数字です。  
障害で Redis が空になると順位も消えます。  
「画面用の速報」と「後から監査するログ」を分けるなら、正のログは RDB に残し、Redis は表示用、という分担になります。

## よくあるつまずき

- 昇順で取るコマンドと `ZREVRANGE` を取り違え、人気順が逆に見える
- メンバーに商品名（表示用の文字列）を入れてしまい、改名するとランキングが分裂する（ID をメンバーにする）
- 期間の切替えをせず、同じキーを何年も `ZINCRBY` し続ける

週が変わったらキーを分ける例: `shop:ranking:2026-w38` のように、期間をキーに含めます。

## まとめ

- ソート済みセットは、メンバーにスコアを付けて順に取り出す
- 加算は `ZINCRBY`、上位の取得は `ZREVRANGE`
- 表示用の順位と、残すべき正のログは分けて考える

次は [TTL とキャッシュ](./ttl-and-cache) で、キーに寿命を付けます。
