# 接続と redis-cli

考え方だけでは、成功時の表示も「無い」の意味も腹落ちしにくいです。  
このページでは Redis へ接続し、対話クライアント **redis-cli** で最初の読み書きをします。

## このページで分かること

- 接続に必要な要素（ホスト、ポート）
- `redis-cli` での接続と、成功・未登録の見え方
- `SET` / `GET` / `DEL` までの最短ルート

## 接続の部品

アプリも `redis-cli` も、だいたい次を揃えて接続します。

| 要素       | よくある値の例       | 意味                     |
| ---------- | -------------------- | ------------------------ |
| ホスト     | `localhost`          | サーバの場所             |
| ポート     | `6379`               | Redis の待ち受けポート   |
| パスワード | 環境で付与されたもの | 認証を有効にしている場合 |

パスワードは必須ではありません。  
手元の検証では認証なし、共有環境ではパスワードがある、という差を先に確認します。

:::warning[本番の接続情報]

本番のホストやパスワードを、検証用ターミナルへ安易に貼らないでください。  
検証用の Redis でも、共有インスタンスなら他人のキーを消す事故が起きます。

:::

## 手元に Redis を用意する

すでに検証用の Redis がある場合は、その接続情報を使ってください。  
手元に何もない場合の一例として、Docker で起動する例を示します。

```bash
docker run --name redis-learn -p 6379:6379 -d redis:7
```

成功時はコンテナ ID のような長い文字列が表示されます。  
`docker ps` で `redis-learn` が `Up` になっていれば起動できています。

<details>
<summary>Docker が使えないとき</summary>

Redis の公式パッケージや、クラウドのマネージド Redis（検証用）でも構いません。  
この章で重要なのはインストール手順そのものより、「接続してコマンドを実行できること」です。

</details>

## redis-cli でつなぐ

クライアントが入っている環境では、次のように接続します。

```bash
redis-cli -h localhost -p 6379
```

成功すると、だいたい次のようなプロンプトになります。

```text
127.0.0.1:6379>
```

ホストとポートが見えていれば、つながっています。  
終了は `QUIT` です。`Ctrl+D` でも抜けられます。

<details>
<summary>Docker コンテナ内の redis-cli を使う例</summary>

ホストに `redis-cli` が無い場合は、コンテナ内で実行できます。

```bash
docker exec -it redis-learn redis-cli
```

</details>

生きているかの確認:

```text
127.0.0.1:6379> PING
PONG
```

`PONG` が返れば、コマンドは届いています。

## 最初の SET と GET

Redis では、**キー**（鍵）に **値** を付けます。  
次を順に実行します。

```text
SET shop:hello world
```

成功時:

```text
OK
```

読み取り:

```text
GET shop:hello
```

成功時:

```text
"world"
```

引用符付きで値が返ります。  
これが「鍵 `shop:hello` の中身は `world`」です。

存在しないキーを読むと、エラーではなく次のようになります。

```text
GET shop:missing
```

```text
(nil)
```

`(nil)` は「その鍵は無い」です。  
表の 0 件に近く、接続が切れたわけではありません。

削除は `DEL` です。

```text
DEL shop:hello
```

成功時:

```text
(integer) 1
```

`1` は削除できたキーの数です。  
無いキーを `DEL` すると `0` になります。

:::tip[結果の読み方]

`OK` や `"値"`、`(nil)`、`(integer) 1` のように、種類ごとに型が付いて返ることが多いです。  
英語のエラーメッセージが出たときだけ失敗、と切り分けると調査が速くなります。

:::

## キーを確認する

学習中に「今どんな鍵があるか」を見るには `KEYS` が使えます。

```text
KEYS shop:*
```

例:

```text
1) "shop:hello"
```

本番の大きな Redis では、`KEYS` は全キーを走査して応答を止めることがあります。  
検証用の少ないキーで一覧を見るコマンド、と覚えておいてください。

<details>
<summary>本番で一覧を取りたいとき</summary>

運用中にキーを順に見るなら `SCAN` を使います。  
一度に全部を列挙せず、カーソルを進めて少しずつ取ります。  
この章の手元検証では `KEYS` で十分です。

</details>

## よくあるつまずき

- PostgreSQL の `5432` に繋いでしまい、応答が返らない
- `GET shop:hello` と打つキーと、`SET` したキーの綴りが違う
- 共有の Redis で `KEYS *` や削除を試し、ほかのアプリのキーまで巻き込む

## まとめ

- 接続にはホストとポート（よくあるのは `6379`）が必要である
- `SET` で書き、`GET` で読む。無いキーは `(nil)` である
- `PING` の `PONG` で、コマンドが届いているかを確認できる
