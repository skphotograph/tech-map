# 確認クイズ

このページでは、つまずきやすいポイントを短く点検します。  
答えは折りたたみの中にあります。  
先に自分の言葉で考えてから開いてください。

## このページで分かること

- 値と参照、到達可能性、文字列比較、コレクションまわりの典型的な誤解を自己点検できる
- 説明できない項目があれば、該当ページへ戻る目印になる

## なぜクイズ形式か

読んだ直後は「分かったつもり」になりやすいです。  
小さな状況問題で手が止まるところは、現場でも同じところで止まります。  
完璧な得点より、**どのページに戻るか** が分かれば十分です。

## Q1. メソッドに渡したあと

次のコードを実行したあと、呼び出し元の `n` と `order` の状態はどうなりますか。

```java
void touch(int n, Order order) {
    n = 99;
    order.setStatus("CLOSED");
    order = new Order("other");
}

int n = 1;
Order order = new Order("ORD-1");
order.setStatus("OPEN");
touch(n, order);
```

- `n` はいくつか
- `order` の status は何か
- `order` の ID は `"ORD-1"` のままか、`"other"` か

<details>
<summary>解答の要点</summary>

- `n` は `1` のまま（プリミティブのコピーを書き換えているだけ）
- status は `"CLOSED"`（同じ Order オブジェクトのフィールドを変更した）
- ID は `"ORD-1"` のまま（メソッド内の `order = new Order(...)` はローカル参照の付け替え）

詳細は [型とメモリ](./types-and-memory) へ。

</details>

## Q2. 文字列の比較

次のうち、**中身が同じ文字列として比較したいとき** に選ぶべきはどれですか。  
また、なぜ他は危険ですか。

```java
String a = readFromRequest(); // 外部入力
String b = "OPEN";

// A: a == b
// B: a.equals(b)
// C: Objects.equals(a, b)
```

<details>
<summary>解答の要点</summary>

- 目的が中身の同値なら **B または C**
- `a` が null の可能性があるなら **C**（または `"OPEN".equals(a)`）が安全
- **A（`==`）** は参照の同一性。入力由来では false になりやすい

詳細は [String と equals](./string-equals) へ。

</details>

## Q3. List の空と null

API が「該当する注文が一件もない」ことを表すとき、次のどちらが呼び出し側にとって扱いやすいことが多いか。  
理由も一言で。

```java
// A
return null;

// B
return List.of();
```

呼び出し側の例:

```java
List<Order> orders = findOrders(userId);
if (orders.isEmpty()) {
    // ...
}
```

<details>
<summary>解答の要点</summary>

- 多くの場合 **B（空リスト）** の方が扱いやすい
- A だと `orders.isEmpty()` の前に null チェックが必要で、忘れれば NPE
- 「結果は存在するが 0 件」と「結果そのものが無い」を分けたいときだけ、null や Optional を検討する

詳細は [コレクションとジェネリクス](./collections-generics) へ。

</details>

## Q4. Set と equals（発展）

`HashSet<UserId>` に `new UserId("u-1")` を入れたあと、別インスタンスの `new UserId("u-1")` で `contains` したら true になってほしい。  
何をクラスに実装しておく必要がありますか。

<details>
<summary>解答の要点</summary>

- `equals` と `hashCode` を、同じ ID なら等しい・同じハッシュになるよう揃える
- `equals` だけだと、ハッシュ表の桶をまたいだ検索で見つからないことがある

詳細は [String と equals](./string-equals) へ。

</details>

## Q5. 到達できないとは

次のうち、作成した `byte[]` が **GC の回収候補になりうる** のはどれに近いですか。  
理由も一言で。

```java
// A
static final Map<String, byte[]> hold = new HashMap<>();
void cache(String id, byte[] pdf) {
    hold.put(id, pdf);
}

// B
void once() {
    byte[] pdf = loadPdf();
    send(pdf);
}
```

<details>
<summary>解答の要点</summary>

- **B** に近い。メソッドを抜けたあと、他から到達できなければ回収候補になる
- **A** は `static` な Map がルートから照らし続けるので、エントリを消さない限り残る
- 「もう使わないつもり」と「到達不能」は別。詳細は [ヒープとガベージコレクション](./heap-and-gc)

</details>

## よくあるつまずき

- クイズの「正解コード」だけ覚えて、理由を説明できない
- null と空、参照の付け替えとフィールド変更を、同じ「変わった／変わらない」で雑にまとめてしまう
