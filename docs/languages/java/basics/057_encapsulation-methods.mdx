# カプセル化と窓口メソッド

注文の状態を外から自由に書き換えられると、想定していない値が入ったり、許可したくない順序で変更されたりします。  
[アクセス修飾子](./access-modifiers) でフィールドを `private` にすると直接の変更は防げますが、外側には「現在の値を知りたい」「注文を確定したい」といった要求が残ります。

そこで、値を読む getter や `close()` のような **意味のある窓口メソッド** を用意します。  
このページでは、外に公開する操作と、内部だけで使う `private` メソッドの分け方を押さえます。

## このページで分かること

- getter（値を読む窓口）の付け方
- 状態を直接書き換えず、意味のある操作（`close()` など）を置く
- 内部用の `private` メソッドで役割を分ける

## getter と意味のある窓口

`private` にしたあと、外から状態を知りたいとき **getter** を置きます。  
命名は `get` + 欄名（先頭大文字）が慣習です。

```java
public class Order {
    private String id;
    private String status;

    public Order(String id, String status) {
        this.id = id;
        this.status = status;
    }

    public String getId() {
        return id;
    }

    public String getStatus() {
        return status;
    }

    public void close() {
        status = "CLOSED";
    }
}
```

```java
Order order = new Order("ORD-1", "OPEN");
order.close();
System.out.println(order.getStatus()); // CLOSED
```

成功例:

```text
CLOSED
```

- `getStatus()` / `getId()` … 今の値を **読む** だけ（欄を書き換えない）
- `close()` … 「閉じる」という **意味のある操作** で状態を変える

`setStatus("CLOSED")` のように setter を機械的に並べると、想定外の文字列が入りやすくなります。  
**許可した操作**（`close` / `confirm` など）をメソッド名にした方が、読み手に意図が伝わります。

:::tip[覚えておくこと]

フィールドは `private`。  
読むなら getter、変えるなら意味のある窓口メソッド。

:::

## 内部だけの手順は `private`

長い計算の一部は、外に見せない `private` メソッドに分けます。

```java
public class PriceLabel {
    public String format(int amount) {
        return prefix() + amount;
    }

    private String prefix() {
        return "yen:";
    }
}
```

```java
System.out.println(new PriceLabel().format(2400));
```

成功例:

```text
yen:2400
```

`format` が外の窓口、`prefix` は内側の部品——[アクセス修飾子](./access-modifiers) の続きです。

## よくあるつまずき

- すべてのフィールドに setter を機械的に付け、規則を外に漏らす
- getter なのに内部状態を書き換えてしまう
- `private` フィールドを別クラスから直接触ろうとする

## まとめ / 次に学ぶとよいこと

- getter は読む窓口。`get` + 欄名が慣習
- 変更は `close()` のような意味のあるメソッドに寄せる
- 内部の部品は `private` メソッドへ分ける
