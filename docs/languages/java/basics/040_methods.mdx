# メソッド

同じ計算をコピペで増やすと、直す場所がバラバラになります。  
「よく使う手順に名前を付ける」——それが **メソッド** です。

Java では、メソッドは **クラスの中** に書きます。  
[最初のプログラム](./first-program) の `main` と同じ入れ物です。  

## このページで分かること

- メソッドの定義と呼び出し
- 引数と戻り値、`void`
- `main` から同じクラスの手順を呼ぶ
- 早期 `return` でネストを浅くする書き方
- 同じ名前で引数が違うメソッド（オーバーロード）

## メソッドは「名前の付いた手順書」

明細の小計を毎回口で説明するより、`calculateLineTotal` と書いた手順書を渡した方が早いです。

```java
public class OrderService {
    static int calculateLineTotal(int quantity, int unitPrice) {
        return quantity * unitPrice;
    }

    public static void main(String[] args) {
        int total = calculateLineTotal(2, 1200);
        System.out.println(total); // 2400
    }
}
```

| 書き方                          | たとえ                                                |
| ------------------------------- | ----------------------------------------------------- |
| `int calculateLineTotal(...)`   | 手順書の名前が `calculateLineTotal`。答えは整数で返す |
| `(int quantity, int unitPrice)` | 材料として渡す数量と単価                              |
| `return quantity * unitPrice`   | 計算結果を呼び出し元へ返す                            |
| `calculateLineTotal(2, 1200)`   | 手順書を実際に使う（呼び出す）                        |

呼び出し側では、返ってきた値を変数に入れたり、そのまま使ったりできます。

```java
System.out.println(calculateLineTotal(1, 450)); // 450
```

:::tip[覚えておくこと]

メソッドは「受け取るもの」「返すもの」「名前」がそろった手順。  
使うときは名前で呼び出す。

:::

## 戻り値が無い処理: `void`

画面に出すだけのように、返事が要らない手順は、戻り値の型に `void` を書きます。

```java
public class OrderService {
    static void printTotal(int total) {
        System.out.println(total);
    }

    public static void main(String[] args) {
        printTotal(2400);
    }
}
```

`void` のメソッドでは、値を `return` しません。  
途中で抜けたいときは、値なしの `return;` も使えます（次の早期 return でも出ます）。

## `main` から同じクラスの手順を呼ぶ

起動の入口 `main` も、クラスの中の手順書のひとつです。  
上の例では、`main` から同じクラスの `calculateLineTotal` / `printTotal` を呼んでいます。

いまは次だけ押さえておけば足ります。

- 手順はクラスの中に書く
- `main` から、同じクラスの `static` な手順を呼べる

ここでの `static` は、「伝票を切らずに呼べる手順（クラスに属する手順）」だと考えてください。

## 早期 return: 入口で弾いて、中をすっきり

`if` が何段も重なると読みにくくなります。  
そこで、すぐ弾ける条件を先に `return` し、下は「通った人だけ」を扱う書き方があります（早期 return）。

注文確定の入口でまず金額を確認し、不正なら細かい割引の前に弾く。  
通った場合だけ、まとめ買い割引のラベルを付ける、といったイメージです。

```java
public class OrderService {
    static String label(int amount) {
        if (amount < 0) {
            return "invalid";
        }
        if (amount >= 1000) {
            return "bulk";
        }
        return "normal";
    }

    public static void main(String[] args) {
        System.out.println(label(1200)); // bulk
        System.out.println(label(-1));   // invalid
    }
}
```

- 最初の `if` で不正ならすぐ返す → その下は「通った人だけ」を扱えるのでシンプルに
- `else` を何段も積み上げなくてよい

すべてを早期 return にする必要はありません。  
枝が深くなって読みにくくなったときに、この形を思い出してください。

## 同じ名前で引数が違う（オーバーロード）

同じ目的の手順でも、渡す材料の個数や型が違うことがあります。  
そのとき **同じ名前のメソッドを、引数の違いで並べる** ことができます（オーバーロード）。

```java
public class OrderService {
    static int applyDiscount(int amount) {
        return amount;
    }

    static int applyDiscount(int amount, int percentOff) {
        return amount - (amount * percentOff / 100);
    }

    public static void main(String[] args) {
        System.out.println(applyDiscount(1000));     // 1000
        System.out.println(applyDiscount(1000, 10)); // 900
    }
}
```

呼び出し側は、渡した引数に合う定義が選ばれます。  
戻り値の型だけを変えて同じ引数にする、はできません（区別できないため）。

:::tip[覚えておくこと]

オーバーロードは「同じ名前・違う引数」。  
戻り値の型だけを変えて同じ引数にする、はできない。

:::

## よくあるつまずき

- メソッドをクラスの外に書いてしまう
- 戻り値の型と `return` の値が合わない
- `void` なのに値を返そうとする／返すメソッドで `return` を忘れる
- 引数の個数や型を呼び出しと定義で食い違わせる
- 戻り値の型だけ違うオーバーロードを書こうとしてコンパイルエラー

## まとめ / 次に学ぶとよいこと

- メソッドはクラスの中に書き、引数を受け取り `return` で返す（または `void`）
- `main` から同じクラスの手順を呼んで組み立てられる
- 早期 `return` で入口で弾くと、中の枝が浅くなる
- 同じ名前で引数が違うメソッドを並べられる（オーバーロード）
