# 実行の仕組み

このページでは、`.java` を書いてからプログラムが動き始めるまでの流れをつかみます。  
「コンパイルして実行する」が、裏で何をしているかのイメージです。

## なぜ実行モデルを先に見るか

エラーメッセージに `ClassNotFoundException` や `NoClassDefFoundError` が出たとき、  
「クラスが見つからない」と言われても、何が足りないのか分かりにくいことがあります。  
`javac` と `java`、JDK と JRE、クラスパスの関係が見えていると、調査の出発点が決まります。

## `.java` から JVM まで

ざっくり次の順です。

1. 人が書くソースファイル（`.java`）
2. コンパイラ `javac` がバイトコード（`.class`）に変換する
3. JVM（Java Virtual Machine）が `.class` を読み込み、マシン向けの命令に落として実行する

```text
Hello.java  --javac-->  Hello.class  --java-->  JVM 上で実行
```

バイトコードは「特定の OS の機械語」ではなく、JVM が解釈できる中間形式です。  
同じ `.class` を、対応する JVM が入った環境へ持っていって動かせる、というのが Java の強みのひとつです。

## JDK / JRE / JVM

名前が似ているので、役割だけ分けて覚えます。

| 名前 | ざっくり言うと | 何がうれしいか |
| ---- | -------------- | -------------- |
| **JVM** | バイトコードを実行するエンジン | OS 差分を吸収して動かす |
| **JRE** | JVM ＋ 実行に必要なライブラリ（歴史的な呼び方） | 実行環境のまとまり |
| **JDK** | 開発に必要な一式（`javac` なども含む） | 書いて・コンパイルして・動かす |

いま手元で学習するなら、**JDK を入れる** と考えておけば足ります。  
`java -version` と `javac -version` が両方通ることを確認しておきましょう。

:::tip[覚えておくこと]

学習・開発では JDK を入れる。  
実行だけならランタイムでも足りるが、教材のコマンドは `javac` 前提です。

:::

## `main` メソッドが入り口

JVM は、指定したクラスの **`public static void main(String[] args)`** を探して起動します。  
ここがプログラムの入口です。

```java
public class OrderApp {
    public static void main(String[] args) {
        System.out.println("order started");
    }
}
```

コンパイルと実行の例です。

```bash
javac OrderApp.java
java OrderApp
```

成功すると、標準出力に次のような一行が出ます。

```text
order started
```

`java OrderApp` のときは、拡張子 `.class` を付けません。  
クラス名（とパッケージがある場合はその完全修飾名）を渡します。

## クラスローディング（入口だけ）

JVM は起動時に、必要なクラスをまとめて全部メモリに載せるわけではありません。  
実行の途中で「このクラスが必要だ」となったタイミングで読み込みます（**クラスローディング**）。  
そのため、「起動はできたのに、ある処理の直前でクラスが見つからない」という失敗もあり得ます。  
階層や同一性の詳細は、節の後半の [JVM とクラスローディング](./jvm-and-classloading) で扱います。  
ここでは「必要なときに読みにいく」と押さえておけば十分です。

## ソースファイルモード（`java Main.java`）

比較的新しい JDK では、単一ファイルなら次のように **コンパイル手順を省略して実行** できます。

```bash
java OrderApp.java
```

内部では一時的にコンパイル相当の処理が行われ、すぐに実行されます。  
小さな確認や教材の試行には便利です。  
複数ファイルや依存ライブラリが絡む本格開発では、これまでどおりビルドツール（後の Maven など）を使う場面が大半です。

<details>
<summary>パッケージがあるときの注意（入口）</summary>

ソース先頭に `package com.example.order;` がある場合、ディレクトリ構造とクラスパスが一致していないと、  
`javac` / `java` の指定方法が変わります。  
まずはパッケージなしの単一ファイルで流れを体感し、パッケージはプロジェクト構成に慣れてからで構いません。

</details>

## よくあるつまずき

- `java OrderApp.class` と書いてしまう（拡張子は不要）
- `javac` は通るのに `java` でクラスが見つからない（カレントディレクトリやクラスパスの問題が多い）
- JDK を入れたつもりだが `javac` だけ通らない（PATH にコンパイラが入っていない）

## まとめ / 次に学ぶとよいこと

- ソース → `javac` → `.class` → JVM 実行、という流れが基本形
- 学習では JDK を入れ、`main` が起動の入口になる
- 単一ファイルなら `java Foo.java` も使える

次は [型とメモリ](./types-and-memory) で、値がどこに置かれ、メソッドにどう渡るかを見ます。
