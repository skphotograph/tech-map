# クラスと new

現場のコードは、数値や文字列だけではありません。  
注文番号と状態のように、**まとめて扱いたいデータ** を型にします。  
それが **クラス** です。

[メソッド](./methods) で「手順に名前を付ける」を見ました。  
ここでは「データと、それに対する操作」をひとまとめにします。

## このページで分かること

- クラス、フィールド、インスタンスメソッド
- `new` で実体を作る
- フィールドの初期値（デフォルト）
- コンストラクタの入口
- 参照型と `null` の入口

## クラスは「伝票のひな型」

たとえで言うと、クラスは「伝票のひな型」、`new` は「実際に一枚切る」です。

説明用に、データの型と起動の入口を同じソースに並べています。  
慣れてきたら、`Order.java` のようにファイルを分けることも多いです。

```java
class Order {
    String id;
    String status;

    void close() {
        status = "CLOSED";
    }
}

public class OrderDemo {
    public static void main(String[] args) {
        Order order = new Order();
        order.id = "ORD-1";
        order.status = "OPEN";
        order.close();
        System.out.println(order.status); // CLOSED
    }
}
```

| 言葉                         | いまの読み方                                                               |
| ---------------------------- | -------------------------------------------------------------------------- |
| フィールド（`id`, `status`） | 伝票に書く欄                                                               |
| メソッド（`close`）          | その伝票に対する操作。`order.close()` のように「どの伝票か」を先に指定する |
| `new Order()`                | 伝票を一枚切る（実体を作る）                                               |
| `Order order`                | 作った伝票を扱うための名前                                                 |

ここまでの `close` は、切った伝票に対する操作です。  
一方、数量と単価から小計を出すような手順は、特定の伝票が無くても呼べます。  
そのときは `static` を付けます。  
上の `Order` と並べて、呼び方の違いを見ます。

```java
public class OrderDemo {
    static int lineTotal(int quantity, int unitPrice) {
        return quantity * unitPrice;
    }

    public static void main(String[] args) {
        int total = lineTotal(2, 1200); // 2400。伝票を切らず、名前で呼ぶ

        Order order = new Order();
        order.status = "OPEN";
        order.close(); // 切った伝票に対して呼ぶ
        System.out.println(total);
        System.out.println(order.status); // CLOSED
    }
}
```

| 呼び方               | たとえ                           |
| -------------------- | -------------------------------- |
| `lineTotal(2, 1200)` | 伝票なしで使える手順（`static`） |
| `order.close()`      | 「この伝票」を指定して呼ぶ手順   |

:::tip[覚えておくこと]

`new` で実体を作り、フィールドで状態を持ち、メソッドで操作する。

:::

複数枚切れます。  
別々の伝票は、別々の状態を持てます。

```java
Order first = new Order();
Order second = new Order();
first.id = "ORD-1";
second.id = "ORD-2";
```

## コンストラクタ: 切る瞬間に欄をそろえる

生成直後に欄をそろえたいときは、コンストラクタを使います。  
「伝票を切る瞬間に、番号と状態も書いておく」イメージです。

```java
class Order {
    String id;
    String status;

    Order(String id, String status) {
        this.id = id;
        this.status = status;
    }
}

Order order = new Order("ORD-1", "OPEN");
```

- コンストラクタの名前はクラス名と同じ
- 戻り値の型は書かない
- `this.id` は「この伝票の欄 `id`」

引数名と欄の名前が同じとき、`id = id` だとどちら向きか分かりません。  
`this.id = id` と書くと、「欄へ、引数の値を入れる」がはっきりします。

## フィールドの初期値（デフォルト）

`new` した直後、欄に値を入れていなくても **型ごとの初期値** が入ります。

| 型        | 初期値（例） |
| --------- | ------------ |
| `int`     | `0`          |
| `boolean` | `false`      |
| `double`  | `0.0`        |
| 参照型    | `null`       |

```java
class Counter {
    int count;
    String label;
}

Counter counter = new Counter();
System.out.println(counter.count);  // 0
System.out.println(counter.label);  // null
```

出力例:

```text
0
null
```

ローカル変数（メソッドの `{ }` の中）には、初期値は自動では付きません。  
フィールドだけが、この表のルールで始まります。

## `null` は「行き先がまだ無い」

`String` や自作クラスのような参照型の欄は、初期値が **`null`** です。  
`null` の欄に `.` で触ると **NullPointerException**（NPE）になります。

```java
class Label {
    String text;
}

Label label = new Label();
// label.text.length(); // 実行時エラー（NPE）
```

[文字列の基本](./string-basics) でも触れたとおり、空文字 `""` と `null` は別物です。

## よくあるつまずき

- `new` せずにフィールドへ触ろうとしてエラーになる
- コンストラクタ名をクラス名と食い違わせる
- `static` な手順と、インスタンスのメソッド（`order.close()`）を混同する
- 複数の `new` なのに、同じ伝票だと思い込む

## まとめ / 次に学ぶとよいこと

- クラスはフィールドとメソッドを持つひな型
- `new` で実体を作り、名前を付けて扱う
- コンストラクタで生成直後の欄をそろえられる
- フィールドには型ごとの初期値がある（参照型は `null`）
