# クラスと new

現場のコードは、数値や文字列だけではありません。  
注文番号と状態のように、**まとめて扱いたいデータ** を型にします。  
それが **クラス** です。

[メソッド](./methods) で「手順に名前を付ける」を見ました。  
ここでは「データと、それに対する操作」をひとまとめにします。

## このページで分かること

- クラス、フィールド、インスタンスメソッド
- `new` で実体を作る
- コンストラクタの入口

## クラスは「伝票のひな型」

たとえで言うと、クラスは「伝票のひな型」、`new` は「実際に一枚切る」です。

説明用に、データの型と起動の入口を同じソースに並べています。  
慣れてきたら、`Order.java` のようにファイルを分けることも多いです。

```java
class Order {
    String id;
    String status;

    void close() {
        status = "CLOSED";
    }
}

public class OrderDemo {
    public static void main(String[] args) {
        Order order = new Order();
        order.id = "ORD-1";
        order.status = "OPEN";
        order.close();
        System.out.println(order.status); // CLOSED
    }
}
```

| 言葉                         | いまの読み方                                                               |
| ---------------------------- | -------------------------------------------------------------------------- |
| フィールド（`id`, `status`） | 伝票に書く欄                                                               |
| メソッド（`close`）          | その伝票に対する操作。`order.close()` のように「どの伝票か」を先に指定する |
| `new Order()`                | 伝票を一枚切る（実体を作る）                                               |
| `Order order`                | 作った伝票を扱うための名前                                                 |

前のページの `static` な手順は、伝票を切らずに呼べました。  
ここでの `close` は、**切った伝票に対して** 呼びます。

| 呼び方          | たとえ                           |
| --------------- | -------------------------------- |
| `add(2, 3)`     | 伝票なしで使える手順（`static`） |
| `order.close()` | 「この伝票」を指定して呼ぶ手順   |

:::tip[覚えておくこと]

`new` で実体を作り、フィールドで状態を持ち、メソッドで操作する。

:::

複数枚切れます。  
別々の伝票は、別々の状態を持てます。

```java
Order first = new Order();
Order second = new Order();
first.id = "ORD-1";
second.id = "ORD-2";
```

## コンストラクタ: 切る瞬間に欄をそろえる

生成直後に欄をそろえたいときは、コンストラクタを使います。  
「伝票を切る瞬間に、番号と状態も書いておく」イメージです。

```java
class Order {
    String id;
    String status;

    Order(String id, String status) {
        this.id = id;
        this.status = status;
    }
}

Order order = new Order("ORD-1", "OPEN");
```

- コンストラクタの名前はクラス名と同じ
- 戻り値の型は書かない
- `this.id` は「この伝票の欄 `id`」

引数名と欄の名前が同じとき、`id = id` だとどちら向きか分かりません。  
`this.id = id` と書くと、「欄へ、引数の値を入れる」がはっきりします。

## よくあるつまずき

- `new` せずにフィールドへ触ろうとしてエラーになる
- コンストラクタ名をクラス名と食い違わせる
- `static` な手順と、インスタンスのメソッド（`order.close()`）を混同する
- 複数の `new` なのに、同じ伝票だと思い込む

## まとめ / 次に学ぶとよいこと

- クラスはフィールドとメソッドを持つひな型
- `new` で実体を作り、名前を付けて扱う
- コンストラクタで生成直後の欄をそろえられる
