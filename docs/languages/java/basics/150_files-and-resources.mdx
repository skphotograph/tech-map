# ファイルとリソース管理

ファイルを読めたことだけ確認して処理を終えると、例外時にストリームが閉じられず、長時間動くアプリケーションで資源不足になることがあります。  
蛇口を開けっぱなしにしたまま席を立つ——ファイル操作も、パスの組み立てとリソースの寿命をはっきりさせる必要があります。

## このページで分かること

- `Path` と `Files` を使う NIO.2 の基本
- 小さなファイルと大きなファイルで読み方を変える理由
- `try-with-resources` と `AutoCloseable` の役割

## Path で場所を表す

`Path` は、ファイルやディレクトリの場所を表します。  
文字列の連結ではなく `resolve` を使うと、区切り文字を実行環境へ任せられます。

```java
Path dataDirectory = Path.of("data");
Path orderFile = dataDirectory.resolve("orders.csv");

System.out.println(orderFile);
```

実行結果の例:

```text
data/orders.csv
```

Windows では区切りが `\` で表示されることがあります。  
どちらも `Path` が実行環境に合わせて表した結果です。

## Files で読み書きする

小さなテキストファイルなら、一度に読み込めます。

```java
List<String> lines = Files.readAllLines(
    orderFile,
    StandardCharsets.UTF_8
);
```

書き込みでは、文字コードとオプションを明示します。

```java
Files.writeString(
    Path.of("data", "status.txt"),
    "completed\n",
    StandardCharsets.UTF_8,
    StandardOpenOption.CREATE,
    StandardOpenOption.TRUNCATE_EXISTING
);
```

`TRUNCATE_EXISTING` は既存内容を切り詰めて置き換えます。  
追記が必要なら `APPEND` を選び、同時書き込みや途中失敗をどう扱うかも検討します。

:::warning[外部入力のパスをそのまま使わない]

利用者が指定した `../` などで許可範囲の外へアクセスできないよう、基準ディレクトリに解決したあとの正規化と範囲確認が必要です。

:::

## 大きなファイルは逐次処理する

`readAllLines` は全内容をメモリに載せます。  
サイズが大きい、または上限が分からないファイルでは、`Files.lines` や `BufferedReader` で逐次処理します。

```java
try (Stream<String> lines =
         Files.lines(orderFile, StandardCharsets.UTF_8)) {
    long validCount = lines
        .filter(line -> !line.isBlank())
        .count();

    System.out.println(validCount);
}
```

`Files.lines` が返す Stream は、背後で開いたファイルを保持します。  
そのため `try-with-resources` で閉じます。

## try-with-resources で確実に閉じる

例外とクローズの考え方の本体は [例外とリソース解放](./exceptions) にあります。  
ここでは NIO.2 の読み書きに、同じ構文を当てはめます。

`AutoCloseable` を実装したオブジェクトは、`try` の丸括弧内で宣言できます。

```java
try (BufferedReader reader = Files.newBufferedReader(
        orderFile,
        StandardCharsets.UTF_8)) {
    String firstLine = reader.readLine();
    System.out.println(firstLine);
}
```

正常終了でも例外終了でも、自動的に `close()` が呼ばれます。  
開けたら閉じる——データベース接続、HTTP クライアントのレスポンス、独自リソースなどにも同じ考え方を適用できます。

```java
final class TemporaryResource implements AutoCloseable {
    @Override
    public void close() {
        System.out.println("resource closed");
    }
}
```

複数のリソースは宣言と逆の順序で閉じられます。

<details>
<summary>close でも例外が起きた場合</summary>

本体の処理と `close()` の両方が例外を投げた場合、本体の例外が主例外になり、クローズ時の例外は suppressed exception として保持されます。  
`Throwable#getSuppressed()` で確認でき、ログ基盤があれば通常はスタックトレースにも表示されます。
</details>

## よくあるつまずき

- OS 固有の区切り文字を文字列として埋め込む
- 大きさが不明なファイルを `readAllBytes` や `readAllLines` で読む
- `Files.lines` の Stream を閉じない
- デフォルト文字コードへ依存する
- 書き込みオプションによる上書きや追記の違いを確認しない

## まとめ

- NIO.2 では場所を `Path`、操作を `Files` で表す
- ファイルサイズに応じて、一括読み込みと逐次処理を選ぶ
- `AutoCloseable` な資源は `try-with-resources` で確実に閉じる
