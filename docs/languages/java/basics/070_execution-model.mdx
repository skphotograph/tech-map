# 実行の仕組み

`javac` は通った。なのに `java` で「クラスが見つからない」。  
このとき困るのは、エラー文言そのものより、**どこを疑えばよいか分からない**ことです。

このページでは、`.java` を書いてからプログラムが動き始めるまでを、地図として押さえます。  
コマンドの暗記を増やすのではなく、「誰が何をしているか」です。

:::tip[復習]

手元での最短ルートは次でした。  
`javac Hello.java` で `.class` を作り、`java Hello` でクラス名を指定して実行する。

:::

## なぜここを見るか

「クラスが見つからない」と言われても、足りないのが次のどれかで打ち手が変わります。

- そもそもコンパイルしていない
- コンパイルはしたが、探す場所が違う
- 開発用の道具（`javac`）が入っていない

`javac` と `java`、JDK と JVM、クラスパス——名前は似ていますが、役割は分かれています。

## `.java` から動き出すまで

流れは短いです。

1. 人が書くソース（`.java`）——レシピ
2. `javac` がバイトコード（`.class`）に変換する——下ごしらえ
3. JVM が `.class` を読み、実行する——盛り付けて出す

```text
Hello.java  --javac-->  Hello.class  --java-->  JVM 上で実行
```

バイトコードは、特定の OS の機械語ではありません。  
JVM が読める中間形式です。  
だから同じ `.class` を、対応する JVM がある環境へ持っていって動かせます。  
書く場所と動かす場所を分けられる——それが Java の強みのひとつです。

## JDK / JRE / JVM

名前が似ているので、役割だけ分けます。  
たとえで言うと、こうです。

| 名前    | たとえ                     | ざっくり言うと                         |
| ------- | -------------------------- | -------------------------------------- |
| **JVM** | 厨房のコンロ               | バイトコードを実行するエンジン         |
| **JRE** | 厨房一式（歴史的な呼び方） | JVM ＋ 実行に必要なライブラリ          |
| **JDK** | 厨房＋包丁まな板セット     | 書いて・コンパイルして・動かす開発一式 |

学習では **JDK を入れる** と考えておけば足ります。  
`java -version` と `javac -version` が両方通ることを確認します。

:::tip[覚えておくこと]

学習・開発では JDK を入れる。  
実行だけならランタイムでも足りる場面もありますが、教材のコマンドは `javac` 前提です。

:::

## `main` は受付の窓口

JVM は、指定したクラスの **`public static void main(String[] args)`** を探して起動します。  
受付の窓口名が決まっているイメージです。窓口が無いと、建物に入れません。

```java
public class OrderApp {
    public static void main(String[] args) {
        System.out.println("order started");
    }
}
```

```bash
javac OrderApp.java
java OrderApp
```

成功すると、次のような一行が出ます。

```text
order started
```

`java OrderApp` のときは、拡張子 `.class` を付けません。  
渡すのはクラス名です。

## クラスは、必要なときに読みにいく

JVM は起動時に、必要なクラスをまとめて全部メモリに載せるわけではありません。  
実行の途中で「このクラスが要る」となったタイミングで読み込みます（**クラスローディング**）。

だから、「起動はできたのに、ある処理の直前でクラスが見つからない」という失敗もあり得ます。  
倉庫の扉は開いた。棚の奥の部品だけが無い——そんな感じです。

## クラスパスは「探しに行く棚」

`java Hello` のとき、JVM は **クラスパス** に並んだ場所から `Hello.class` を探します。  
何も指定しないと、多くの環境ではカレントディレクトリ（`.`）がクラスパスに入ります。  
だから、ソースと同じディレクトリで `javac` した直後に `java Hello` すると見つかることが多いです。

```bash
# カレントに Hello.class がある前提
java Hello

# 探し先を明示する例（区切りは OS による。Linux/macOS は : 、Windows は ; ）
java -cp . Hello
```

依存ライブラリの jar が増えると、クラスパスに複数の場所を並べます。  
現場では Maven などが組み立てを肩代わりすることが多いです。

:::tip[クラスが見つからないとき]

まず疑うのは次のふたつです。  
今のカレントに `.class` があるか。  
`-cp` の指定は合っているか。

:::

## ソースファイルモード（`java Main.java`）

比較的新しい JDK では、単一ファイルならコンパイル手順を省略して実行できます。

```bash
java OrderApp.java
```

小さな確認には便利です。  
複数ファイルや依存が絡む本格開発では、ビルドツールを使う場面が大半です。

<details>
<summary>パッケージがあるときの注意（入口）</summary>

ソース先頭に `package com.example.order;` がある場合、ディレクトリ構造とクラスパスが一致していないと、  
`javac` / `java` の指定方法が変わります。  
まずはパッケージなしの単一ファイルで流れを体感して構いません。

</details>

## よくあるつまずき

- `java OrderApp.class` と書いてしまう（拡張子は不要）
- `javac` は通るのに `java` でクラスが見つからない（カレントやクラスパス）
- JDK を入れたつもりだが `javac` だけ通らない（PATH にコンパイラが無い）

## まとめ / 次に学ぶとよいこと

- ソース → `javac` → `.class` → JVM 実行、が基本形
- 学習では JDK を入れ、`main` が起動の入口になる
- クラスパスは「どこを探すか」。見つからないときは棚を疑う
