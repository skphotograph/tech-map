# Java をはじめよう

この章では、業務システムでもよく使われる言語 **Java** を学びます。  
ゴールは文法の暗記ではなく、レビュー、障害調査、フレームワーク学習で必要になる **実行の仕組み・型と参照・メモリ・基本 API・ビルド・設計の入口** をつなげて理解することです。  
例は架空の EC サイト（商品・注文・在庫）でそろえ、現場でよく出るデータの形に寄せています。

## この章の進め方

共通基盤の Git や Linux と同じく、**書き方の入口から** 積み上げます。  
入門に必要な書き方は、**入門編で一通り網羅** します。入門編を通し終えてから、実行・メモリ・標準 API の本編へ進みます。途中で飛ばさないのが基本です。

入門編で押さえること:

- 変数・型・四則演算、`if` / `for`、メソッドの定義と呼び出し
- `class` を書いて `new` する、フィールドの読み書き
- アクセス修飾子（`public` / `private` など）の入口
- 配列と簡単な `List`
- 手元で `javac` / `java`、または IDE から小さなプログラムを動かす

本編で厚く扱うこと:

- 値と参照の違い、スタックとヒープ（先に地図を持つ）
- その後の GC・リーク調査、`equals` / 例外・ジェネリクスや Stream
- Maven、設計原則、DI や REST などのアプリ部品の見方

:::info[読み方の目安]

はじめて近い人は、[Java 言語](./basics/) の **入門編**（ロードマップ 1〜8）を順に通してから、[実行の仕組み](./basics/execution-model) 以降へ進んでください。  
すでに入門文法が手に馴染んでいる人は、入門編を流し読みしても構いませんが、実行・メモリのページに入る前に、自分の穴がないかだけ確認してください。

:::

## この章で分かること

- 小さな Java プログラムを書いて動かす入口
- Java がどうコンパイルされ、JVM 上で動くか
- 値と参照、ガベージコレクション、コレクション、例外、現代的な構文の使いどころ
- Maven による依存管理とビルドの考え方
- OOP と設計原則の入口、Web アプリ寄りの中立的な部品（DI・REST・データアクセスなど）

## こんな場面で効く

「 NullPointerException の意味が分からない」  
「なぜ `==` で文字列比較してはいけないと言われるのか」  
「GC があるのにヒープが減らない」  
「フレームワークのアノテーションが、裏側で何をしているのか想像できない」

土台が見えていると、ライブラリやサーバの話が「魔法」ではなくなります。  
道具の使い方と、倉庫の地図がつながる、という感覚です。

:::tip[この章のゴール]

手元で Java の基本を追い、メモリと実行のイメージを持ち、ビルドと依存の感覚を持ったうえで、Web アプリでよく出る部品を中立的に説明できる状態を目指します。

:::

## 学習のロードマップ

1. [Java 言語](./basics/) … 入門編、実行モデル、メモリと GC、例外、コレクション、標準 API、JDBC、並行処理、アノテーション、クラスローディング
2. [Maven](./maven/) … 依存解決とビルドの標準的な道具
3. [設計の入口](./design/) … OOP・原則・アーキテクチャの見取り図
4. [アプリケーション部品](./applications/) … DI・REST・データアクセスなどをスタック非依存で整理

フレームワークは特定製品に寄せません。  
Jakarta EE も Spring も、現場ではどちらも出てきます。  
ここでは共通する考え方を先に持ち、各スタックの細部は公式ドキュメントや配属先の案内に任せます。

[共通基盤](../../foundations/)（Git / Linux など）を先に読んでおくと、コマンド例や調査の型が追いやすいです。  
HTTP の用語は共通基盤側の章が揃うまでのあいだ、[REST API と DTO](./applications/rest-and-dto) の最低限の表でも足ります。
