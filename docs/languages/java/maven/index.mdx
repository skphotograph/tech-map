# Maven

手元ではコンパイルできたのに、別の環境ではライブラリが足りずに動かない。  
テストの実行方法や成果物の作り方が人によって違い、リリース前に手順を確認し直す。  
Maven は、このようなビルドと依存関係のばらつきを、設定と規約でそろえるための道具です。  

## この章で分かること

- `pom.xml` が表すプロジェクト情報と依存関係
- ライフサイクルに沿ってコンパイル、テスト、パッケージ化する流れ
- 依存関係のスコープ、競合、推移的依存を調査する方法
- プラグイン、プロファイル、`settings.xml` の役割分担
- マルチモジュール構成と、ビルドが失敗したときの調べ方

## Maven を学ぶ理由

Java のビルドでは、ソースコードのコンパイルだけでなく、ライブラリの取得、テスト、成果物の作成、配布までを再現できる必要があります。  
Maven は `pom.xml` にプロジェクトの情報を記述し、決められたライフサイクルに沿って同じ手順を実行します。  
開発者の端末でも CI でも同じコマンドを使えるため、「誰が実行したか」に左右されにくいビルドを作れます。  

:::tip[この章のゴール]

コマンドを暗記するだけでなく、POM、ライフサイクル、依存関係、プラグインの役割を切り分けて、ビルド結果やエラーを説明できる状態を目指します。  

:::

## 学習のロードマップ

1. [Maven の全体像と POM](./overview-and-pom) … 座標、packaging、依存関係、POM の骨格を学ぶ
2. [ビルドライフサイクル](./lifecycle) … フェーズとゴールを区別してビルドを実行する
3. [依存関係の管理](./dependencies) … スコープ、推移的依存、競合の調査と制御を学ぶ
4. [ビルド設定と settings.xml](./build-and-settings) … プラグイン、プロファイル、リポジトリ接続を整理する
5. [マルチモジュールと運用](./multimodule-and-ops) … 複数モジュールの構成とトラブルシューティングを学ぶ

コマンド例は Maven 3.9 系と Java 17 以降を基準にしています。  
実際のプロジェクトでは、Maven Wrapper がある場合は `mvn` の代わりに Windows では `mvnw.cmd`、Linux や macOS では `./mvnw` を使うと、Maven のバージョンをそろえやすくなります。  

## まとめ

- Maven は依存関係とビルド手順を `pom.xml` で共有する
- 規約に沿ったライフサイクルにより、開発端末と CI で同じ流れを再現できる
- 依存関係、プラグイン、環境固有設定を分けて理解すると調査しやすい
