# Python をはじめよう

この章では、スクリプトからデータ処理、Web API、自動化まで幅広く使われる言語 **Python** を学びます。  
ゴールは文法の暗記ではなく、レビュー、障害調査、ライブラリ学習で必要になる **実行の仕組み・値と参照・例外・モジュール・型ヒント・仮想環境** をつなげて理解することです。  
例は架空の EC サイト（商品・注文・在庫）でそろえ、現場でよく出るデータの形に寄せています。

## この章の進め方

共通基盤の Git や Linux と同じく、**書き方の入口から** 積み上げます。  
ただし入門書の網羅はしません。最低限の構文をそろえたら、すぐに参照・例外・型・依存管理の本編へ進みます。

最初の数ページで押さえること:

- 変数・計算、`if` / `for`、関数の定義と呼び出し
- リスト・辞書の読み書き
- 手元で小さな `.py` を動かす
- `import` でファイルを分ける入口

本編で厚く扱うこと:

- 可変（ミュータブル）と不変（イミュータブル）、参照の共有
- `is` と `==`、`None` と truthy / falsy
- クラス、例外、内包表記、ファイル操作
- 型ヒントと静的チェックの入口
- venv とパッケージ管理

:::info[読み方の目安]

すでに入門文法が手に馴染んでいる人は、[Python 言語](./basics/) の先頭（書き方の最低限）を流し読みし、[実行の仕組み](./basics/execution-model) から本編に入って構いません。  
はじめて近い人は、先頭から順に「動かす → 読む」を優先してください。

:::

## この章で分かること

- 小さな Python プログラムを書いて動かす入口
- インタプリタ上でコードがどう実行されるか
- 値と参照、比較、クラス、例外、標準ライブラリの使いどころ
- 型ヒントを付け、ツールで確認する流れ
- venv / pip（または同等の道具）による依存管理の考え方
- HTTP クライアントやテストなど、アプリ寄りの部品の見方

## こんな場面で効く

「リストを渡したのに、呼び出し元まで中身が変わっている」  
「`if data:` が意図せず `False` になる」  
「同じ仮想環境だと思っていたら、別の Python を見ていた」  
「フレームワークの関数が、どの形の値を受け取って返すのか読み取れない」

土台が見えていると、ライブラリやフレームワークのコードでも、値がどこから来てどこへ渡るかを追いやすくなります。

:::tip[この章のゴール]

手元で Python の基本を追い、参照と例外のイメージを持ち、型ヒントと仮想環境の感覚を持ったうえで、よく出る部品を中立的に説明できる状態を目指します。

:::

## 学習のロードマップ

1. [Python 言語](./basics/) … 書き方の最低限、実行モデル、参照、比較、クラス、例外、内包表記、ファイル
2. [型ヒント](./typing/) … 注釈、Optional / Union、ジェネリクスの入口、チェックツール
3. [venv とパッケージ管理](./tooling/) … 仮想環境、依存、`pyproject.toml` の入口
4. [アプリケーション部品](./applications/) … HTTP クライアント、テスト、構成の見取り図

フレームワークは特定製品に寄せません。  
Django も FastAPI も Flask も、現場ではどれも出てきます。  
ここでは共通する考え方を先に持ち、各スタックの細部は公式ドキュメントや配属先の案内に任せます。

[共通基盤](../../foundations/)（Git / Linux など）を先に読んでおくと、コマンド例や調査の型が追いやすいです。  
すでに [Java](../java/) や [JavaScript / TypeScript](../javascript-typescript/) を読んでいる人は、「実行と参照」「依存管理」の感覚を、この章の地図に載せ替えて読めます。

## まとめ / 次に学ぶとよいこと

- Python の書き方だけでなく、実行・参照・例外・型・依存管理をつなげて学ぶ
- 書き方に不安があれば言語の先頭から、基本文法に慣れていれば実行の仕組みから進める
- 型ヒント、環境管理、アプリケーション部品へ順番に範囲を広げる

次は [Python 言語](./basics/) で、最初のプログラムから実行と参照の地図を作ります。
