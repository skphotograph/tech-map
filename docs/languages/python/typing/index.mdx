# 型ヒントをはじめよう

関数名は分かるのに、文字列を渡すのか辞書を渡すのか分からない。  
動かしてから、返り値が `None` になる経路に気づく。  
型ヒントは、値の形をコード上の約束として共有し、こうした食い違いを実行前に見つけやすくします。  

## この節で分かること

- 型ヒントが必要な理由と、実行時との役割分担
- 変数、コレクション、関数への基本的な注釈
- `None` を含む型、ユニオン型、型エイリアス
- `TypeVar` と `Protocol` による再利用の入口
- mypy や Pyright で型を確認する流れ

## 型ヒントは確認の材料

Python は、型注釈を書かなくても実行できる動的型付け言語です。  
型ヒントを加えると、エディタの補完、レビュー、静的型チェッカーが「期待する形」を読み取れます。  

TypeScript と同じく、狙いは型名を増やすことではありません。  
関数の入口と出口、データの形を明示し、変更による食い違いを早い段階で見つけることです。  

:::info[型注釈だけでは検査されない]

Python の型注釈は、通常は実行時に値を拒否しません。実行前の確認には mypy や Pyright などの静的型チェッカーを使います。  

:::

コード例は Python 3.11 以降を基準にします。  
Python 3.10 で導入された `X | None` や `list[str]` など、現在よく使われる書き方を中心に扱います。  

## まとめ

- 型ヒントは入力・出力・データの形を共有する
- 型注釈は通常、実行時の検証を行わない
- 静的型チェッカーと組み合わせると食い違いを早く検出できる

次は [型ヒントが必要な理由](./why-type-hints) で、実行時エラーとの違いから確認します。
