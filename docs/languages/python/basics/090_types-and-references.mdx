# 型と参照

「別名を付けただけのつもりが、元のリストまで変わっている」。  
Python でリストや辞書を扱うと、この現象に出会うことがあります。  
代入は、いつでも値の複製を作る操作ではないためです。

## このページで分かること

- 変更できない値と、変更できる値の違い
- 再代入と、オブジェクト自体の変更の違い
- 複数の変数が同じリストを参照する仕組み
- スライスと `copy.copy` で浅いコピーを作る方法

## 変数はオブジェクトを指す名前

Python では、数値や文字列、リストなどを **オブジェクト** として扱います。  
変数はオブジェクトを入れる箱というより、オブジェクトを指す名前だと考えると、代入後の動きを理解しやすくなります。

```python
status = "OPEN"
current_status = status
```

この時点では、`status` と `current_status` は同じ文字列 `"OPEN"` を指しています。  
ただし、文字列は中身を変更できないオブジェクトです。

## イミュータブルな値は変更できない

作成後に中身を変更できない性質を **イミュータブル** と呼びます。  
よく使うイミュータブルな型には、`int`、`str`、`tuple` があります。

```python
quantity = 3
copied_quantity = quantity

copied_quantity = 5

print(quantity)         # 3
print(copied_quantity)  # 5
```

`copied_quantity = 5` は、整数 `3` を書き換えたのではありません。  
`copied_quantity` が別の整数 `5` を指すように、名前とオブジェクトの結び付きを変えています。  
この操作を **再代入** と呼びます。

文字列でも同じです。

```python
first_status = "OPEN"
second_status = first_status

second_status = "CLOSED"

print(first_status)   # OPEN
print(second_status)  # CLOSED
```

`second_status` を再代入しても、`first_status` が指す文字列は変わりません。

:::tip[再代入は元の値を書き換えない]

イミュータブルな値への再代入は、変数が指す先を別のオブジェクトへ変える操作です。

## ミュータブルな値は中身を変更できる

作成後に中身を変更できる性質を **ミュータブル** と呼びます。  
`list`、`dict`、`set` は代表的なミュータブルな型です。

変数を別の変数へ代入しても、リストそのものは複製されません。  
ふたつの変数が、同じリストを指す状態になります。

```python
first_items = ["book"]
second_items = first_items

second_items.append("pen")

print(first_items)   # ['book', 'pen']
print(second_items)  # ['book', 'pen']
```

`append` は、`second_items` の指す先を変える操作ではありません。  
両方の変数が指しているひとつのリストに、要素を追加する操作です。  
そのため、`first_items` から見ても `"pen"` が追加されています。

辞書や集合も同じように参照を共有します。

```python
first_order = {"status": "OPEN"}
second_order = first_order

second_order["status"] = "CLOSED"

print(first_order["status"])  # CLOSED
```

この共有は、関数へリストや辞書を渡す場面でも起こります。  
受け取った側で中身を変更すると、呼び出し元から見える内容も変わります。

:::tip[参照共有が分かるとうれしいこと]

「関数の中だけ直したはずなのに、呼び出し元の一覧も変わった」という不具合を、バグではなく **同じオブジェクトを共有している** と説明できます。  
意図せず共有したくないときは、コピーを渡すか、関数側で新しいリストを作る、という打ち手が選べます。

:::

## 浅いコピーで外側を分ける

リストを別々に変更したいときは、スライス `[:]` でコピーを作れます。

```python
original_items = ["book"]
copied_items = original_items[:]

copied_items.append("pen")

print(original_items)  # ['book']
print(copied_items)    # ['book', 'pen']
```

標準ライブラリの `copy.copy` でも同じく浅いコピーを作れます。

```python
import copy

original_order = {"status": "OPEN"}
copied_order = copy.copy(original_order)

copied_order["status"] = "CLOSED"

print(original_order["status"])  # OPEN
```

どちらも **浅いコピー** です。  
外側のリストや辞書は新しくなりますが、内側にあるミュータブルなオブジェクトまでは複製されません。

```python
original = [["book"]]
copied = original[:]

copied[0].append("pen")

print(original)  # [['book', 'pen']]
```

`original[0]` と `copied[0]` は、同じ内側のリストを指しています。  
まずは「浅いコピーは外側の一段を分ける」と捉えてください。

## よくあるつまずき

- 代入すれば、リストや辞書の内容も複製されると思い込む
- 再代入と、`append` などによる中身の変更を混同する
- タプルを変更できると思い、要素へ代入しようとする
- 浅いコピーで、入れ子のリストまで独立したと考える

## まとめ / 次に学ぶとよいこと

- `int`、`str`、`tuple` はイミュータブルで、中身を変更できない
- `list`、`dict`、`set` はミュータブルで、中身を変更できる
- 代入したふたつの変数が、同じミュータブルなオブジェクトを参照することがある
- `list[:]` と `copy.copy` は、外側の一段を分ける浅いコピーを作る
