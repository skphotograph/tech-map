# アプリケーション部品

文法が読めても、通信、テスト、設定が一度に現れると入口を見失います。  
特定のフレームワークへ進む前に、多くのアプリケーションに共通する部品と境界を整理します。  

## この節で分かること

- 入力・処理・出力へ分ける見方
- HTTP 通信のタイムアウトと失敗の扱い
- 小さな自動テストの書き方
- ソース、テスト、設定を分ける構成

## 学習のロードマップ

1. [アプリケーションの見取り図](./overview) … 外部境界と中心の処理を分ける
2. [HTTP クライアント](./http-clients) … 成功・失敗・タイムアウトを扱う
3. [テストの基本](./testing-basics) … 振る舞いを自動確認する
4. [プロジェクト構成](./project-shape) … コードと設定の置き場所をそろえる

例は Python 3.11 以降を基準にします。  
HTTP の例では一つのライブラリを使いますが、判断の軸はほかのクライアントやフレームワークでも共通です。  

:::tip[この節のゴール]

ライブラリ名ではなく、外部との境界、失敗の扱い、テスト可能な分け方を説明できる状態を目指します。  

:::

## まとめ

- 外部境界と中心の処理を分けて考える
- 通信には失敗と待ち時間の上限を設計する
- テストと構成で変更の影響を確認しやすくする

次は [アプリケーションの見取り図](./overview) で、部品を分ける基準を確認します。
