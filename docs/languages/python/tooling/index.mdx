# venv とパッケージ管理

同じコマンドなのに、端末によってパッケージが見つからない。  
Python 本体と依存パッケージをプロジェクト単位でそろえると、こうした環境差を減らせます。

## この節で分かること

- `venv` で環境を分ける方法
- pip でパッケージを操作する方法
- `pyproject.toml` に依存関係を書く考え方
- ロックファイルや固定一覧でインストールを再現する方法

## 学習のロードマップ

1. [venv と pip](./venv-and-pip) … 環境を作り、使っている Python を確認する
2. [pyproject.toml と依存関係](./pyproject-and-dependencies) … プロジェクト情報と直接依存を宣言する
3. [再現可能なインストール](./reproducible-installs) … 解決された依存バージョンを共有する

例は Python 3.11 以降と標準の `venv`、pip を基準にします。  
既存プロジェクトでは README、`pyproject.toml`、ロックファイルを確認し、採用済みの管理ツールを使ってください。

:::tip[この節のゴール]

空の環境から、プロジェクトが指定する Python と依存関係を導入し、確認コマンドを実行できる状態を目指します。

:::

## まとめ

- 仮想環境はプロジェクト間のパッケージの混線を防ぐ
- 依存関係は端末の状態ではなくファイルで共有する
- 許容する条件と実際に導入する固定バージョンは役割が異なる

次は [venv と pip](./venv-and-pip) で、分離した環境を作ります。
