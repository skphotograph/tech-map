# JavaScript アプリケーションの全体像

ブラウザで動いたコードを Node.js へ移したら、`document is not defined` と表示される。  
同じ JavaScript でも、コードを動かす場所が変われば、周囲に用意されている機能も変わります。

前の npm の節では、依存関係と実行コマンドをプロジェクトでそろえました。  
ここからは、そのプロジェクト内のコードがブラウザとサーバーでどの役割を担うかを見ていきます。

## このページで分かること

- JavaScript の言語と実行環境の違い
- フロントエンドとバックエンドの主な役割
- HTTP を境界にデータを受け渡す流れ
- 共通コードを分けるときの注意点

## 同じ言語、異なる実行環境

JavaScript の構文や配列、Promise などは、ブラウザでも Node.js でも共通して使えます。  
一方、画面やサーバーへ接続する機能は、JavaScript を実際に動かす周囲の環境が提供します。  
この周囲の環境を **ホスト環境** と呼びます。このページでは、ブラウザと Node.js がホスト環境に当たります。

ここでいう **API** は、コードから環境の機能を呼び出すための窓口です。  
たとえば `document` はブラウザが提供する API です。HTTP で呼び出す「注文 API」とは、文脈が異なります。

- ブラウザ：`document`、画面イベント、Web Storage などを提供する
- Node.js：ファイルシステム、プロセス、サーバー機能などを提供する

たとえば `document.querySelector(...)` はブラウザが提供するため、通常の Node.js プロセスには存在しません。  
反対に、Node.js のファイル操作をブラウザからそのまま使うこともできません。

## フロントエンドの役割

フロントエンドは、主に利用者のブラウザで動きます。  
画面を表示し、入力を受け取り、必要なデータをバックエンドへ要求します。

たとえば注文画面なら、次のような責務があります。

- 入力欄と注文一覧を表示する
- ボタン操作を受け取る
- 入力形式をその場で確認する
- HTTP で注文 API を呼び出す
- 応答に応じて成功やエラーを表示する

ブラウザへ配布したコードやデータは、利用者から確認できる前提で扱います。  
API キーやパスワードなどの秘密情報を、フロントエンドのコードへ埋め込んではいけません。

## バックエンドの役割

バックエンドは、主にサーバー上で動きます。  
HTTP リクエストを受け、業務ルールを適用し、必要に応じてデータベースや外部サービスへ接続します。

注文 API なら、次のような責務があります。

- リクエストの形式と権限を確認する
- 在庫や金額のルールを適用する
- データを保存する
- 処理結果を HTTP レスポンスとして返す
- 運用に必要なログを記録する

ブラウザ側の入力確認は操作を助けますが、サーバー側の確認を置き換えません。  
リクエストは改変できるため、守るべきルールはバックエンドでも検証します。

:::tip[境界ごとに責務を考える]

フロントエンドは利用者との対話、バックエンドは信頼できない入力を受けてルールとデータを守る役割を中心に考えます。

:::

## HTTP でつながる

フロントエンドとバックエンドは、同じ言語を使っていても別のプロセスとして動くことがあります。  
その境界では、関数を直接呼ぶのではなく HTTP のリクエストとレスポンスを使います。

```text
ブラウザ
  └─ GET /api/orders ──> サーバー
  <─ 200 + JSON ────────┘
```

JSON はデータを受け渡す形式であり、JavaScript のオブジェクトそのものではありません。  
送信時には文字列へ変換され、受信側で解析されます。

## 共通コードに向くもの

フロントエンドとバックエンドで同じ言語を使うと、環境に依存しない処理を共有できる場合があります。

- 金額計算のように、画面やファイルへ依存しない処理
- 入出力の型定義
- 共通の入力形式を確認する処理

ただし、画面操作とデータベース操作までひとつのモジュールへ混ぜると、どちらの環境でも扱いにくくなります。  
共有するのは、ブラウザや Node.js 固有の API に依存しない部分を基本にします。

## よくあるつまずき

- JavaScript ならどの環境でも同じ API が使えると思う
- ブラウザへ秘密情報を埋め込む
- フロントエンドの入力確認だけを信頼し、サーバーで検証しない
- HTTP 越しの処理を、同じプロセス内の関数呼び出しと同じ感覚で扱う
- 環境固有の処理まで無理に共通化する

## まとめ / 次に学ぶとよいこと

- JavaScript の言語機能は共通でも、ホスト環境が提供する API は異なる
- フロントエンドは利用者との対話、バックエンドはルールとデータの保護を担う
- 別プロセス間では HTTP と JSON が境界になる
- 共通化するなら、実行環境に依存しない処理を選ぶ
