# アプリケーション部品

JavaScript の文法は同じでも、ブラウザのコードとサーバーのコードでは、使える機能や担う役割が違います。  
さらに実務のプロジェクトには、通信、テスト、設定、複数のディレクトリが一度に現れます。  
製品名を追う前に共通する役割をつかむと、初めて見る構成でも入口を見つけやすくなります。

## この章で分かること

- フロントエンドとバックエンドの実行環境と役割
- `fetch` で HTTP の成功・失敗と JSON を扱う方法
- 小さな自動テストで期待する振る舞いを確かめる方法
- `src/`、UI、業務ロジック、設定を分ける考え方

## 製品名より先に境界を見る

React や Vue は画面側、Express や Fastify はサーバー側で見かける代表的な名前です。  
ただし、この章では特定のフレームワークを前提にしません。  
どのスタックでも現れる「どこで動くか」「外部とどう通信するか」「何をテストするか」「どこへコードを置くか」を学びます。

:::tip[この章のゴール]

フレームワーク固有の書き方がなくても、実行環境、通信境界、テスト対象、コードの責務を説明できる状態を目指します。

:::

## まとめ

- JavaScript は複数の実行環境で動き、環境ごとに利用できる機能が異なる
- 通信、テスト、構成にはフレームワークをまたいだ共通の考え方がある
- 製品名ではなく、部品の責務と境界からコードを読む
