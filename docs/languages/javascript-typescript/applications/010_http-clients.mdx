# HTTP クライアント

`fetch` で通信し、例外が出なかったので成功だと思ったら、実際にはサーバーが `404 Not Found` を返していた。  
通信できたことと、要求した処理が成功したことは別です。  
HTTP クライアントでは、状態コード、本文、通信自体の失敗を分けて扱います。

## このページで分かること

- `fetch` で HTTP リクエストを送る方法
- `response.ok` で状態コードを確認する理由
- JSON のレスポンスを読み取る方法
- HTTP エラーと通信エラーを扱う方法

## `fetch` は Promise を返す

ここでは Node.js 20 以降または現代的なブラウザの `fetch` を使います。  
`fetch` は Promise を返すため、`async` 関数の中で `await` して応答を受け取れます。

```js
async function loadOrder(orderId) {
  const response = await fetch(`https://api.example.com/orders/${orderId}`);
  return response;
}
```

`await` は Promise の結果が決まるまで、その `async` 関数の続きの実行を待ちます。  
プログラム全体やブラウザ全体を停止するわけではありません。

## 状態コードを確認する

`fetch` は、サーバーから `404` や `500` が返っても、通常は `Response` を受け取る Promise として成功します。  
HTTP として応答を受け取れたためです。  
要求した処理の成否は、`response.ok` や `response.status` で別に確認します。

```js
async function loadOrder(orderId) {
  const response = await fetch(`https://api.example.com/orders/${orderId}`);

  if (!response.ok) {
    throw new Error(`注文の取得に失敗しました: ${response.status}`);
  }

  return response.json();
}
```

`response.ok` は、状態コードが `200` から `299` の範囲なら `true` です。  
失敗時に状態コードを含めると、認証不足なのか、対象がないのか、サーバー側の問題なのかを調べる手掛かりになります。

:::tip[fetch の直後に状態を確認する]

`await fetch(...)` が完了しただけでは業務上の成功とは限りません。  
本文を成功データとして使う前に `response.ok` を確認します。

:::

## JSON を読み取る

`response.json()` も Promise を返します。  
JSON 本文を読み、JavaScript の値へ変換する処理だからです。

```js
async function showOrder(orderId) {
  const response = await fetch(`https://api.example.com/orders/${orderId}`);

  if (!response.ok) {
    throw new Error(`注文の取得に失敗しました: ${response.status}`);
  }

  const order = await response.json();
  console.log(`${order.id}: ${order.status}`);
}
```

HTTP レスポンスの本文は一度読み取ると消費されます。  
同じレスポンスに対して `response.json()` を何度も呼ばないようにします。

また、JSON を解析できても、必要な項目や型が保証されたわけではありません。  
外部 API のデータを重要な処理へ渡す前には、仕様に沿った形かを境界で確認します。

## HTTP エラーと通信エラーを扱う

呼び出し側では `try` / `catch` を使い、状態確認で投げたエラーと、接続できない場合などの失敗を受け止めます。

```js
async function main() {
  try {
    const response = await fetch('https://api.example.com/orders/ORD-1001');

    if (!response.ok) {
      throw new Error(`HTTP ${response.status}`);
    }

    const order = await response.json();
    console.log(order.id);
  } catch (error) {
    console.error('注文を表示できませんでした', error);
  }
}

main();
```

通信エラーの例には、名前解決の失敗、接続不能、通信の中断があります。  
JSON の形式が壊れていれば、`response.json()` も失敗します。

画面では利用者向けの短い案内を表示し、ログには調査に必要な状態コードやエラーを残す、というように伝える相手を分けます。  
レスポンス本文には機密情報が含まれる場合があるため、無条件にすべてをログへ出してはいけません。

## POST で JSON を送る

JSON を送るときは、メソッド、ヘッダー、本文を指定します。

```js
async function createOrder(order) {
  const response = await fetch('https://api.example.com/orders', {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
    },
    body: JSON.stringify(order),
  });

  if (!response.ok) {
    throw new Error(`注文の作成に失敗しました: ${response.status}`);
  }

  return response.json();
}
```

`JSON.stringify(order)` は JavaScript のオブジェクトを JSON 文字列へ変換します。  
`Content-Type` は送る本文が JSON であることをサーバーへ伝えます。

## よくあるつまずき

- `fetch` が完了しただけで処理成功と判断し、`response.ok` を確認しない
- `response.json()` の `await` を忘れる
- 同じレスポンス本文を複数回読み取る
- 外部から来た JSON の形を無条件に信頼する
- エラー応答や機密情報をそのまま画面やログへ出す

## まとめ / 次に学ぶとよいこと

- `fetch` は Promise を返し、HTTP エラーでも通常は `Response` を受け取る
- `response.ok` と `response.status` で要求の成否を確認する
- `response.json()` にも `await` が必要
- HTTP エラー、通信エラー、JSON 解析エラーを考慮する
- JSON を送るときは `Content-Type` と `JSON.stringify` を使う
