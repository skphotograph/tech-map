# npm と開発ツール

自分の端末では動いたのに、別の人の端末ではライブラリが見つからない。  
実行コマンドを口頭で伝えた結果、オプションが抜けて動きが変わる。  
npm は、こうした依存関係と実行手順のばらつきを、プロジェクトのファイルでそろえるための道具です。

## この章で分かること

- `package.json` が表すプロジェクト情報
- 実行時と開発時の依存関係の分け方
- `scripts` を使って共通の手順を実行する方法
- `package-lock.json` がインストール結果を安定させる理由

## 依存とコマンドがバラバラになる場面

JavaScript のプロジェクトは、自分で書いたコードだけでは成り立たないことがあります。  
HTTP サーバー、テスト、コード整形などの機能をパッケージとして取り込み、チームで同じ手順を実行する必要があるためです。

npm はパッケージを取得するだけでなく、`package.json` を中心にプロジェクトの情報とコマンドを共有します。  
Java の Maven に触れたことがあれば、`pom.xml` と依存取得・ビルドコマンドを、JavaScript の流儀に置き換えたものと考えると入りやすいでしょう。  
ただし、ファイル形式やライフサイクルの考え方は同じではありません。

:::tip[この章のゴール]

`package.json` とロックファイルの役割を分け、依存関係の追加から共通コマンドの実行までを説明できる状態を目指します。

:::

## 学習のロードマップ

1. [npm と package.json](./npm-and-package-json) … プロジェクト情報を用意し、npm の基本操作を試す
2. [依存関係と scripts](./dependencies-and-scripts) … パッケージの分類と共通コマンドを理解する
3. [ロックファイルとインストール](./lockfile-and-install) … 再現しやすいインストールと更新の流れを学ぶ

例は Node.js 20 以降と npm 10 以降を基準にしています。  
既存プロジェクトでは、README、ロックファイル、`package.json` を確認します。  
`package.json` に `engines` があれば、そこで Node.js などの対応バージョンが示されています。プロジェクトが指定するバージョンとパッケージ管理ツールを使ってください。

## まとめ

- npm はパッケージの取得とプロジェクト共通の手順を扱う
- `package.json` はプロジェクト情報、依存関係、コマンドを共有する中心になる
- `package-lock.json` は実際に解決された依存関係を記録する

次は [npm と package.json](./npm-and-package-json) で、最小のプロジェクトを作るところから始めましょう。
