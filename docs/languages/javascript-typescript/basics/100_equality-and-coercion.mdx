# 等価と比較

入力された `"0"` と数値の `0`。  
見た目は似ていますが、プログラムにとっては文字列と数値という別の値です。  
JavaScript が気を利かせて型を変換すると、意図しない条件まで通ることがあります。

## このページで分かること

- `===` と `!==` を使った安全な比較
- `==` が行う暗黙の型変換と、その注意点
- truthy / falsy を使った条件判定
- `if (value)` が適する場面と、適さない場面

## 比較には `===` を使う

ふたつの値が等しいか調べるときは、基本的に **厳密等価演算子** `===` を使います。  
値と型の両方が同じ場合だけ `true` になります。

```js
console.log(10 === 10); // true
console.log('10' === '10'); // true
console.log('10' === 10); // false
```

等しくないことを調べる演算子は `!==` です。

```js
const status = 'OPEN';

if (status !== 'CLOSED') {
  console.log('処理中の注文です');
}
```

文字列の `"10"` と数値の `10` は、見た目が似ていても型が違います。  
`===` は勝手に型をそろえないため、入力や HTTP API から受け取った値に型の食い違いがあっても見逃しにくくなります。

等しいかは `===`、等しくないかは `!==` を使います。

:::

## `==` は比較の前に型を変換する

`==` は **抽象等価演算子** と呼ばれ、型が違う値を比較するときに暗黙の型変換を行います。

```js
console.log('5' == 5); // true
console.log(false == 0); // true
console.log('' == 0); // true
```

この例を暗記する必要はありません。重要なのは、`==` ではコードに書かれていない変換まで考えないと結果を判断できないことです。  
たとえば数量を数値で扱う設計なのに、フォームから受け取った文字列 `"0"` が数値の `0` と等しい扱いになると、変換し忘れた場所を見逃します。後続の足し算で文字列連結になるなど、比較より離れた場所で不具合が現れることもあります。

初心者のうちは `==` を避け、必要な型変換を明示してから `===` で比較するのが安全です。

```js
const input = '5';
const quantity = Number(input);

if (quantity === 5) {
  console.log('数量は 5 です');
}
```

`Number(input)` と書けば、「文字列を数値として扱いたい」という意図がコードに残ります。  
暗黙の変換へ任せるより、読み手も変換の場所を確認しやすくなります。

## truthy と falsy

`if` の条件には真偽値以外も書けます。  
その場合、JavaScript は値を真偽値として評価します。  
条件で `false` として扱われる値を **falsy**、`true` として扱われる値を **truthy** と呼びます。

よく使う値のうち、falsy になるものは次のとおりです。

- `false`
- `0`（`-0` も含む）
- `0n`（`bigint` のゼロ）
- `""`（空文字列）
- `null`
- `undefined`
- `NaN`

それ以外の多くの値は truthy です。

```js
if ('OPEN') {
  console.log('文字列は truthy');
}

if ([]) {
  console.log('空の配列も truthy');
}

if ({}) {
  console.log('空のオブジェクトも truthy');
}
```

空の配列 `[]` と空のオブジェクト `{}` も truthy です。  
「中身が空だから falsy」とはならない点に注意してください。

## `if (value)` を使う場面

値が存在し、かつ空でないことだけを確かめたい場合は、`if (value)` が簡潔です。

```js
const userName = 'Aiko';

if (userName) {
  console.log(`こんにちは、${userName}さん`);
}
```

この形では、`userName` が `undefined`、`null`、`""` などなら処理されません。  
名前のように、空文字列を「入力なし」と見なせる値に向いています。

一方、`0` や `false` が正しい値になり得る場合は、`if (value)` では区別できません。

```js
const stock = 0;

if (stock !== undefined) {
  console.log(`在庫数: ${stock}`);
}
```

在庫数 `0` は「値がない」のではなく、「在庫がゼロ」という意味のある値です。  
何を判定したいのかに合わせて、`===` や `!==` で条件を具体的に書きます。

<details>
 <summary>NaN を調べる方法</summary>

`NaN` は数値への変換に失敗した結果などで現れる特別な値です。  
`NaN === NaN` は `false` になるため、判定には `Number.isNaN(value)` を使います。

```js
const quantity = Number('five');
console.log(Number.isNaN(quantity)); // true
```

</details>

## よくあるつまずき

- `==` の暗黙の型変換で、型の食い違いを見逃す
- `"0"` も falsy だと思い込む
- 空の配列や空のオブジェクトを falsy だと考える
- `if (value)` で、意味のある `0` や `false` まで「値なし」と扱う
- `NaN` を `NaN === NaN` で判定しようとする

## まとめ / 次に学ぶとよいこと

- 比較には、型を勝手に変換しない `===` と `!==` を使う
- `==` は暗黙の型変換を行うため、意図しない一致が起こりやすい
- `false`、`0`、`""`、`null`、`undefined`、`NaN` は falsy
- `if (value)` は、`0` や `false` も値として必要な場面では使い分ける
