# Promise

サーバーへデータを取りに行っている間、画面全体が止まってしまっては困ります。  
一方で、まだ届いていない結果を今すぐ使うこともできません。  
「結果はあとで渡します」という約束を表すのが **Promise** です。

前のページの `throw` は、その場で進んでいる処理の失敗を伝えました。  
通信やタイマーの結果はあとで決まるため、Promise は成功した値だけでなく、あとで決まった失敗も呼び出し元へ伝えます。

## このページで分かること

- 非同期処理に Promise が必要な理由
- Promise の成功と失敗を `then` / `catch` で扱う方法
- `new Promise(...)` と `Promise.resolve(...)` の基本
- `Promise.all(...)` で複数の結果を待つ方法

## Promise は「あとで結果を渡す」入れ物

通常の関数は、呼び出すとその場で結果を返します。

```js
function calculateTotal(price, quantity) {
  return price * quantity;
}

const total = calculateTotal(500, 3);
console.log(total); // 1500
```

通信やタイマーのような処理は、結果が得られるまで時間がかかります。  
その間も JavaScript はほかの処理を進め、結果の準備ができたあとで続きを実行します。  
Promise は、その未来の結果を表すオブジェクトです。

Promise には次の 3 つの状態があります。

- `pending`：処理中
- `fulfilled`：成功し、結果が得られた
- `rejected`：失敗し、理由が得られた

一度 `fulfilled` または `rejected` になると、別の状態には変わりません。

## `then` で成功、`catch` で失敗を扱う

すでに成功した Promise は `Promise.resolve(...)` で作れます。

```js
const orderPromise = Promise.resolve({
  id: 'ORD-1',
  status: 'OPEN',
});

orderPromise
  .then((order) => {
    console.log(order.id);
  })
  .catch((error) => {
    console.error(error.message);
  });
```

実行結果です。

```text
ORD-1
```

Promise が成功すると `then` に渡したコールバックが呼ばれ、成功した値を受け取ります。  
失敗すると `catch` に渡したコールバックが呼ばれ、エラーを受け取ります。

:::tip[成功と失敗の入口]

Promise の成功結果は `then`、失敗理由は `catch` で受け取ります。

:::

## `then` のコールバックはあとで動く

成功済みの Promise であっても、`then` のコールバックは今の同期処理が終わったあとに実行されます。

```js
console.log('1: 開始');

Promise.resolve().then(() => {
  console.log('3: Promise の続き');
});

console.log('2: 終了');
```

実行結果です。

```text
1: 開始
2: 終了
3: Promise の続き
```

コード上では `then` が先に見えても、`"2: 終了"` が先に出力されます。  
JavaScript は実行中の同期処理を最後まで進め、その後で Promise のコールバックを実行するためです。  
この順序は、非同期処理の結果を変数へ入れて直後に使おうとしたとき、特に重要になります。

## `new Promise` で非同期処理を包む

完了したときに関数を呼んで知らせる形式の非同期処理などを Promise として扱いたいときは、`new Promise(...)` を使えます。

```js
function wait(milliseconds) {
  return new Promise((resolve) => {
    setTimeout(() => {
      resolve('待機完了');
    }, milliseconds);
  });
}

wait(1000).then((message) => {
  console.log(message); // 1 秒ほどあとに "待機完了"
});
```

`new Promise` に渡した関数は、Promise を作った時点ですぐに実行されます。  
この関数の中で、処理が成功したら `resolve(value)`、失敗したら `reject(error)` を呼びます。`resolve` と `reject` は、あとで結果を受け取る側へ成功か失敗かを伝えるための関数です。

```js
function loadOrder(orderId) {
  return new Promise((resolve, reject) => {
    if (!orderId) {
      reject(new Error('注文 ID が必要です'));
      return;
    }

    resolve({
      id: orderId,
      status: 'OPEN',
    });
  });
}

loadOrder('')
  .then((order) => {
    console.log(order);
  })
  .catch((error) => {
    console.error(error.message);
  });
```

実行結果です。

```text
注文 ID が必要です
```

`reject` には文字列ではなく `Error` オブジェクトを渡すと、メッセージやスタック情報を利用できます。  
なお、すでに Promise を返す関数をさらに `new Promise` で包む必要はありません。

## `then` をつないで処理を組み立てる

`then` から値を返すと、次の `then` がその値を受け取ります。

```js
Promise.resolve(3000)
  .then((amount) => {
    return amount * 1.1;
  })
  .then((amountWithTax) => {
    console.log(amountWithTax); // 3300
  })
  .catch((error) => {
    console.error(error.message);
  });
```

`then` の中で例外が発生した場合や、返した Promise が失敗した場合も、後ろの `catch` へ伝わります。

```js
Promise.resolve({ id: '' })
  .then((order) => {
    if (!order.id) {
      throw new Error('注文 ID がありません');
    }
    return order;
  })
  .then((order) => {
    console.log(order.id);
  })
  .catch((error) => {
    console.error(error.message);
  });
```

途中の失敗を最後の `catch` でまとめて扱えるため、成功の流れを上から下へ追いやすくなります。

## `Promise.all` で複数の結果を待つ

互いに依存しない複数の Promise をまとめて待つには `Promise.all(...)` を使います。

```js
const orderPromise = Promise.resolve({ id: 'ORD-1' });
const userPromise = Promise.resolve({ name: 'Aiko' });

Promise.all([orderPromise, userPromise])
  .then(([order, user]) => {
    console.log(`${user.name}: ${order.id}`);
  })
  .catch((error) => {
    console.error(error.message);
  });
```

実行結果です。

```text
Aiko: ORD-1
```

すべて成功すると、渡した順番どおりの配列で結果を受け取ります。  
どれかひとつでも失敗すると、`Promise.all(...)` 全体が失敗し、`catch` へ進みます。

並行して始められる処理に使うと、ひとつずつ完了を待つより効率よく結果をそろえられます。  
ただし、一部の失敗を許容したい場合には別の設計が必要です。

## よくあるつまずき

- Promise の結果を、`then` の直後に同期的な変数として使おうとする
- `then` の中で値や Promise を `return` せず、次へ `undefined` が渡る
- 失敗を扱う `catch` を付けず、原因を確認しにくくする
- すでに Promise を返す処理を、不要な `new Promise` で包む
- 順番に待つ必要がない処理まで直列につなぎ、時間を余計にかける

## まとめ / 次に学ぶとよいこと

- Promise は、あとで得られる非同期処理の結果を表す
- 成功は `then`、失敗は `catch` で扱う
- `then` のコールバックは、現在の同期処理が終わったあとに実行される
- `new Promise` では `resolve` と `reject` で成功と失敗を伝える
- `Promise.all` は複数の Promise がすべて成功するのをまとめて待つ
