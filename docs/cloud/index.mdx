# クラウド

サーバやデータベースを、機器の購入やラックへの搬入から始めなくても、必要な分をネットワーク越しに借りられるのがクラウドです。  
構築は速くなります。一方で、サービスの選択、権限、料金、障害時の責任範囲を理解せずに使うと、公開設定のミスや消し忘れた検証環境といった、別の難しさが前面に出ます。

このカテゴリでは、まずクラウドに共通する考え方を押さえ、そのあと [GCP](./gcp/)、[AWS](./aws/)、[Azure](./azure/) で同じ構成がどう呼ばれるかを対応づけます。  
製品カタログを暗記するのではなく、要件に合うサービスと、安全に触る境界を判断できることを目指します。

## 章立て

1. [クラウドの考え方](./fundamentals/) … 借り方の種類、障害の範囲、権限、計算・保存・ネットワーク、料金
2. [GCP](./gcp/) … プロジェクト、`gcloud`、Cloud Storage、Compute Engine、Cloud Run、Cloud SQL
3. [AWS](./aws/) … アカウント、AWS CLI、S3、VPC と EC2、ロードバランサ、RDS
4. [Azure](./azure/) … サブスクリプション、Azure CLI、Blob、仮想ネットワークと VM、App Service、Azure Database

## おすすめの学び方

先に [クラウドの考え方](./fundamentals/) を通すと、あとの 3 章は「同じ箱の別の商品名」として読めます。  
現場で触るクラウドが決まっているなら、考え方のあとでその事業者だけを深く追い、残りは対応表として参照するので十分です。

仮想マシンに入る操作は [リモートアクセス](../foundations/remote-access/) と [Linux / Shell](../foundations/linux/) が土台になります。  
マネージドデータベースの中身は、クラウドの画面より先に [SQL / RDB](../data/sql-rdb/) 側の話です。
