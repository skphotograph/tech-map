# 保存

アプリのディスクがいっぱいになり、注文画面が 500 を返し始める。  
原因は、商品画像を全部仮想マシンの中に置いていたことでした。  
クラウドでは、**計算の隣にあるディスク** と、**HTTP で読み書きするオブジェクトの置き場** は別物です。ここを混ぜると、容量・公開範囲・バックアップの話が全部ずれます。

## このページで分かること

- ブロック（ディスク）、ファイル、オブジェクトの違い
- バケットの公開設定が事故になりやすい理由
- 注文データと画像・PDF の置き分け

## 三種類の保存

| 種類             | たとえ                     | 使い方のイメージ              | 注文システムでの例         |
| ---------------- | -------------------------- | ----------------------------- | -------------------------- |
| **ブロック**     | マシンに挿したディスク     | OS から `/var` として見える   | 仮想マシンのルートディスク |
| **ファイル**     | 共有フォルダ（NFS に近い） | 複数マシンから同じパスで読む  | 複数 VM で共有したい設定群 |
| **オブジェクト** | 名前の付いたファイルの倉庫 | キー（パス）で PUT / GET する | 商品画像、請求書 PDF       |

ブロックは、仮想マシンや一部のマネージドサービスに付く容量です。  
いっぱいになれば OS もアプリも止まります。ログのローテーションや、画像をここに溜めないことが効きます。

オブジェクトストレージは、バケット（入れ物）の中に、キーと中身を置きます。  
容量はディスクより桁で伸ばしやすく、計算資源とは独立して消せます。  
アプリ基盤のようにローカルディスクが揮発しても、画像の正はバケット側に残ります。

```text
orders 表（RDB）          オブジェクトストレージ
order_id = 1001           invoices/1001.pdf
image_key = products/12   products/12.jpg
```

表には「どのキーか」を残し、実体はバケットへ、が基本の分け方です。

## 公開範囲が事故になる

オブジェクトストレージは、URL で取れるように設定できます。  
商品のサムネイルを公開したい、は正当な要件です。  
同じ操作で、請求書や利用者のアップロードまで公開してしまうと、漏洩になります。

開発者がレビューで見るのは、だいたい次です。

- バケット全体が匿名読み取りになっていないか
- 「公開してよいプレフィックス」と「非公開のプレフィックス」が分かれているか
- アプリは、実行環境の身分で **必要なオブジェクトだけ** 読み書きしているか

:::warning[バケットの公開は、設定ミスがすぐに漏洩になる]

ネットワークの穴は、届く人が限られることもあります。  
匿名読み取りのオブジェクトは、URL を知った人に広く取れます。  
検証で公開し、本番と同じ名前規則のまま残す、が定番の失敗です。

:::

## 耐久性とバックアップは別

オブジェクトストレージは、複数箇所に複製される製品が多く、「ディスク 1 本の故障で消える」は起きにくいです。  
それでも、次は別問題です。

- 誤って消した、上書きした（操作ミス）
- ライフサイクルで、想定より短い日数で消した
- 自分たちで管理する暗号鍵を無くした

**バージョニング** や、別バケットへの複製は、操作ミスへの備えです。  
「耐久性が高い」と「昨日の誤削除を戻せる」は同じではありません。  
RDB のバックアップと同じく、戻し方を一度は確認します。

<details>
<summary>ブロックとオブジェクトの料金イメージ</summary>

ディスクは、付けている容量に対して課金されやすいです。空でも枠を確保します。  
オブジェクトは、置いている量と、読み書き回数、転送に対して課金されやすいです。  
ログを無期限にバケットへ流し続けると、保存量が見えないうちに増えます。料金の話は [料金とコスト感覚](./billing) で続けます。

</details>

## よくあるつまずき

- 画像もログも、仮想マシンのディスクに置き続けて満杯になる
- 公開 URL が便利なので、請求書も同じバケットの匿名読み取りにする
- 削除保護もバージョニングも無く、操作ミスで戻し方がない

## まとめ

- ディスクはマシンに付く容量、オブジェクトは計算から独立した倉庫である
- 注文の正は RDB、画像や PDF の実体はバケット、表にはキーを残す
- 耐久性が高くても、公開設定と誤削除への備えは別である
