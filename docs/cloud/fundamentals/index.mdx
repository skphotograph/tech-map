# クラウドの考え方をはじめよう

この章では、特定の画面操作の前に、**クラウドでシステムを組むときの共通言語** を学びます。  
GCP、AWS、Azure は商品名と操作が違いますが、リージョン、権限、仮想ネットワーク、オブジェクトストレージ、マネージド DB といった部品の役割は共通です。  
ここが分かると、現場の構成図やチケットが「知らない製品の羅列」ではなく、「どの箱を、誰が、どこまで責任を持つか」として読めます。

## この章で分かること

- クラウドが速くする部分と、自分たちに残る設計・運用
- IaaS / PaaS / SaaS と、障害時の責任分界
- リージョンとゾーン、計算・保存・ネットワークの役割分担
- 人間とアプリの身分（IAM）、料金の見方
- 業務の Web アプリでよく出る形（負荷分散、アプリ、DB、オブジェクトストレージ）

## こんな場面で効く

注文 API の改修は終わっているのに、「検証用サーバが来週届く」と言われてリリースが止まる。  
逆に、画面から仮想マシンを起動できたのに、データベースを世界中から触れる設定のまま公開してしまう。  
検証用に立ち上げた環境を消し忘れ、翌月の請求だけが残る。

クラウドは、箱を用意する待ち時間を短くします。  
その代わり、**何を借りるか・誰に触らせるか・いくらまで使うか** は、開発者も含めたチームの判断になります。  
この章はその判断の地図です。

:::tip[この章のゴール]

構成図の箱を「計算・保存・ネットワーク・データ・権限」に分解し、障害と公開範囲と料金のどこが自分たちの責任かを説明できる状態を目指します。

:::
