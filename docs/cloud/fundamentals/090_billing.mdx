# 料金とコスト感覚

検証用の仮想マシンを金曜に起動し、月曜に消し忘れた。  
スペックは大きく、ディスクも付けたまま。翌月の請求だけが残ります。  
クラウドの速さの裏で、**動いている時間と、置いている量と、外へ出した通信** が請求になります。開発者も、自分の検証がいくらになるかを見積もれる必要があります。

## このページで分かること

- よくある課金の軸（時間、容量、回数、転送）
- 検証で効く消し忘れ
- 予算アラートと、ラベル（タグ）

## 何に対して払うか

製品ごとに細則は違いますが、感覚は次で足ります。

| 軸           | 例                                         | 開発者が踏む忘れ方               |
| ------------ | ------------------------------------------ | -------------------------------- |
| 時間         | 仮想マシンが起動している時間               | 休日も付けたまま                 |
| 割り当て容量 | ディスク、固定 IP、予約したスループット    | 中身が空でも枠に対して払う       |
| 回数         | オブジェクトの PUT/GET、関数の呼び出し     | ループで API を叩き続ける        |
| 転送         | リージョン外やインターネットへ出した通信量 | 大きな画像を毎回アプリ経由で返す |
| ログ         | 取り込んだログの量と保管期間               | デバッグログを本番で全文、無期限 |

「使った分だけ」は、電源を切った仮想マシンのディスクや、付けたままの公開 IP まで無料、という意味ではありません。  
停止と削除は別操作です。ディスクと IP を残すと、マシンを止めても請求が残ることがあります。

:::warning[検証は削除までがセット]

起動できたことは、成功の半分です。  
作業が終わったら、計算・ディスク・IP・ロードバランサ・DB まで、残っていないかを一覧で確認します。

:::

## 高いものと、安く見えて増えるもの

仮想マシンの大型、マルチゾーンの DB、常時起動の負荷分散は、請求書で目立ちやすいです。  
一方、次は小さく始まって、あとから効きます。

- オブジェクトストレージに、ビルド成果物やログを無期限保管
- NAT や負荷分散の、時間課金
- データ転送（特に外向き）
- 同じ画像を、毎回アプリから世界へ返す（キャッシュや CDN の設計不足）

無料枠やクレジットは、期間と上限があります。  
個人の支払い方法を、会社の本番に使わないでください。請求の主体と、誰が止められるかが分からなくなります。

## 予算とラベル

多くの事業者は、**予算アラート**（一定額を超えたらメール）を持てます。  
検証プロジェクトでは、少額でも先に付けておくと、消し忘れの発見が早くなります。  
アラートは停止を保証しません。通知を見て、人が消す必要があります。

**ラベル**（AWS ではタグ、GCP ではラベル、Azure ではタグ）は、資源に `env=dev`、`team=shop` のような印を付ける仕組みです。  
請求をチームや環境で分解するときの手がかりになります。  
「誰の検証か分からない大型 VM」を減らすための、地味で効く習慣です。

<details>
<summary>見積もりの順番</summary>

1. 常時起動するもの（VM、DB、負荷分散）の時間単価 × 台数
2. ストレージの GB と、バックアップの複製
3. 外向き転送と、オブジェクトのリクエスト
4. ログの量

キャンペーンで台数を増やす話は、1 が効きます。  
画像配信の話は、3 が効きます。  
アプリの `DEBUG` を本番に残す話は、4 が効きます。

</details>

## よくあるつまずき

- コンソールの一覧フィルタが「起動中」だけになっていて、停止済みのディスクを見落とす
- 個人のカードで検証し、退職後も資源が残る
- ログの保管期間を「とりあえず 1 年」にし、アプリ本体よりログ代が大きい

## まとめ

- 課金は時間・容量・回数・転送・ログなど、製品ごとに軸が違う
- 停止と削除は別で、検証は残存資源の一覧確認まで行う
- 予算アラートとラベルは、消し忘れと内訳の手がかりになる
