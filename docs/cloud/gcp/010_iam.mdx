# IAM とサービスアカウント

アプリ用の鍵ファイルを Git にコミットし、そのサービスアカウントがプロジェクトの Editor だと、リポジトリが漏れた瞬間に検証も本番も同じ被害になります。  
GCP では、人間の Google アカウントと、アプリ用の **サービスアカウント** を分けます。

## このページで分かること

- ロールをプリンシパルへ付ける、という形
- サービスアカウントを実行環境に付ける理由
- 鍵ファイルを原則発行しないこと

## 誰に、どのロールを

[アカウントと IAM](../fundamentals/iam-and-accounts) の言葉どおり、GCP も「プリンシパル + ロール + 資源」です。  
プロジェクト全体に付けるロールと、バケットなど資源単位に付けるロールがあります。  
開発の最初はプロジェクト Viewer、必要な操作だけ追加、が事故を小さくします。

よく見るロールの例です。名前は目安です。本番ではカスタムロールや資源単位に寄せます。

| ロールの例            | できることのイメージ   |
| --------------------- | ---------------------- |
| Viewer                | 見る                   |
| Storage Object Viewer | バケット内の読み取り   |
| Cloud SQL Client      | Cloud SQL へ接続する側 |
| Editor / Owner        | 変更や IAM まで広い    |

Owner や Editor を日常のデプロイに使わない、が [責任分界](../fundamentals/shared-responsibility) の具体化です。

プロジェクトの IAM を見る例です。出力は長いので、方針だけ確認します。

```bash
gcloud projects get-iam-policy shop-dev-123456
```

成功時は、`bindings` の下に `role` と `members` が並びます。  
`user:you@example.com` が人間、`serviceAccount:shop-api@...` がアプリの身分です。

## サービスアカウント

**サービスアカウント** は、アプリやバッチのための身分です。  
メールアドレス形式の ID を持ちます。例: `shop-api@shop-dev-123456.iam.gserviceaccount.com`

作成例:

```bash
gcloud iam service-accounts create shop-api --display-name="shop-api"
```

成功時:

```text
Created service account [shop-api].
```

この身分に、例えばバケットへのオブジェクト作成だけを付けます。  
プロジェクト Editor を付けると、[最小権限](../fundamentals/iam-and-accounts) の逆です。

仮想マシンやアプリ基盤には、「このサービスアカウントとして動く」を実行環境へ設定します。  
アプリのコードは、鍵ファイルを読まず、実行環境のメタデータから短いトークンを受け取る、が基本です。

:::warning[JSON 鍵をリポジトリに置かない]

`gcloud iam service-accounts keys create` は、長期の秘密をファイルに出します。  
手元検証の都合でも Git に含めず、発行したらローテーションと無効化の担当を決めます。  
仮想マシンやアプリ基盤では、鍵を出さずに実行環境へサービスアカウントを付ける方法を先に使います。

:::

## 人間の操作

コンソールと `gcloud auth login` は人間です。  
多要素認証と、組織のログインポリシーは、会社のルールに従います。  
個人の Gmail の上に会社の本番を建てない、は [料金](../fundamentals/billing) と権限の両方の話です。

## よくあるつまずき

- 403 が出るたびに Editor を足し、原因のロールが分からなくなる
- コンソールの自分と、アプリ実行環境のサービスアカウントが別なのに、同じ権限だと思う
- 鍵を無効化したあと、どのバッチがそれを使っていたか不明で止まる

## まとめ

- 人間のアカウントとサービスアカウントを分け、ロールは仕事の範囲にする
- 実行環境へ身分を付け、JSON 鍵を Git に置かない
- Owner / Editor は日常のデプロイに使わない
