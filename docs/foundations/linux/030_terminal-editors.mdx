# ターミナルのテキストエディタ

ファイルは作れても、中身を直す手段が無いと実務が止まります。  
特に SSH 先のサーバでは、手元の GUI エディタが使えないことが普通です。  
ここでは、端末だけで文章や設定を編集する定番を押さえます。

## このページで分かること

- なぜターミナルエディタが必要か
- `nano` / `vim`（と `vi`）/ `emacs` の位置づけ
- それぞれ「開く・直す・保存して閉じる」までの基本操作

## なぜ必要か

ログを見るだけなら `less` で足ります。  
一方で、設定ファイルを一行直す・スクリプトを書く、となると **編集** が必要です。  
サーバに入った瞬間、「いつものエディタが無い」はよくあるつまずきです。

:::tip[まずは逃げ道を一つ]

最初に覚えるなら **`nano`** が無難です。  
メニューが画面下に出るので、キーを忘れても手がかりがあります。  
あわせて、サーバに入りがちな **`vim`（または `vi`）の終了と保存** だけは別途押さえておくと安心です。

:::

:::tip[小ネタ: vim 対 emacs、そして第三者]

昔から、端末エディタ界隈では **vim 派と emacs 派の対立** がネタにされてきました。  
どちらが正しいか、というより文化とキーバインドの好みの話です。  
近年の開発端末では、その争いの結果を待たず **VS Code（やその系統のエディタ）が日常の編集を持っていった**、という見方もよくされます。

それでも SSH 先の最小構成サーバでは、いまなお `vi` / `vim` / `nano` が頼れる味方です。  
「手元は VS Code / Cursor、遠隔の緊急編集は nano か vim」——この二刀流が現実的です。

:::

## 比較（ざっくり）

| エディタ         | 特徴                                           | 向き                                 |
| ---------------- | ---------------------------------------------- | ------------------------------------ |
| **nano**         | 操作が素直。下部にショートカット表示           | 初めての端末編集、短い修正           |
| **vim** / **vi** | モードあり。多くのサーバに近いものが入っている | 本番サーバでの定番。慣れると速い     |
| **emacs**        | 高機能。Ctrl 組み合わせが多い                  | 愛用者向け。最小サーバには無いことも |

`vi` は伝統的な実装、`vim` はその高機能版、くらいの理解で始められます。  
コマンド名が `vi` でも、中身が vim 相当の環境は多いです。

## nano：まずこれ

`nano` は、ターミナル向けの比較的素直なテキストエディタです。

**基本的な使い方:**

1. `nano ファイル` で開く（無ければ新規）
2. 普通に文字を打って編集する
3. 保存は Ctrl+O → Enter
4. 終了は Ctrl+X（保存していない変更があれば確認される）

```bash
cd ~/training-linux
nano notes/editor-practice.txt
```

画面イメージ:

```text
  GNU nano ...
  notes/editor-practice.txt

  hello from nano

  ^G Help  ^O Write Out  ^X Exit  ^J Justify  ...
```

読み方のポイント:

- 中央 … 編集中の本文
- 下部の `^O` など … `^` は Ctrl キー。`^O` は Ctrl+O
- 保存時にファイル名確認が出たら、Enter で確定することが多い

<details>
<summary>よく使うショートカット</summary>

- Ctrl+O … 保存
- Ctrl+X … 終了
- Ctrl+W … 検索
- Ctrl+K … 行カット
- Ctrl+U … 貼り付け

</details>

## vim：モードがある編集

`vim` は、入力モードとコマンドモードなどを切り替えて使うテキストエディタです。  
最初の壁は「文字を打っても入力されない」「閉じ方が分からない」です。

**基本的な使い方（これだけ覚える）:**

1. `vim ファイル` で開く
2. 挿入したいとき `i` を押す（INSERT と出たら入力できる）
3. 入力し終わったら Esc で通常モードに戻る
4. 保存して終了は `:wq` と打って Enter
5. 保存せず終了は `:q!` と打って Enter

```bash
vim notes/editor-practice.txt
```

画面イメージ（通常モード）:

```text
hello from nano
~
~
"notes/editor-practice.txt" 1L, 16B
```

`i` のあと:

```text
-- INSERT --
```

読み方のポイント:

- 左下や下部の `-- INSERT --` … 入力モード。文字が本文に入る
- 表示が消えていて、打ったキーがコマンドになる … 通常モード（ここで `:wq`）
- `:` で始まる行 … コマンド行。保存・終了などはここ

:::warning[閉じ込められたら]

焦って適当にキーを連打しない。  
いったん Esc を数回押し、`:q!` → Enter で抜けられます（保存しません）。

:::

<details>
<summary>もう少しだけ便利な操作</summary>

- `h` `j` `k` `l` … 左・下・上・右へ移動（通常モード）
- `dd` … 行削除
- `u` … 取り消し
- `/文字` … 検索（`n` で次へ）
- `:w` … 保存だけ
- `:q` … 終了（変更があると拒否される）

</details>

<details>
<summary>`vi` と `vim`</summary>

古い解説やサーバでは `vi` と書かれていることがあります。  
操作感は近いので、このページの「開く・`i`・Esc・`:wq`」は流用できることが多いです。  
高機能な設定やプラグインの話は、必要になってからで十分です。

</details>

## emacs：高機能なもう一つの系譜

`emacs` は、編集だけでなく拡張性の高いターミナル／GUI 両用のエディタ文化を持つツールです。  
Ctrl と Meta（Alt）の組み合わせが基本操作になります。

**基本的な使い方（入口）:**

1. `emacs ファイル` で開く（環境によっては GUI が起動することがある。端末に閉じたいときは `emacs -nw ファイル`）
2. 普通に入力して編集する
3. 保存は Ctrl+X のあと Ctrl+S
4. 終了は Ctrl+X のあと Ctrl+C

```bash
emacs -nw notes/editor-practice.txt
```

`-nw` は、ウィンドウではなく端末内で開く指定です。

読み方のポイント:

- 下部のミニバッファ … 保存確認やメッセージが出る場所
- キーは「コードを暗記」より、チートシートを見ながら慣れる方が早い

最小のクラウドイメージには入っていないことも多いです。  
必須というより、チームや個人の好みで選ぶ位置づけ、と捉えてください。

## どれを使うか

- **初めて / 急いで直す** … `nano`
- **サーバに入っていて nano が無い / 同僚が vim 前提** … `vim`（終了と保存だけでも）
- **愛用している / 環境に揃っている** … `emacs`

手元の日常編集は VS Code や Cursor でも構いません。  
このページの目的は、**端末しか無いときに詰まらないこと** です。

## よくあるつまずき

| 症状                      | よくある原因             | 方向性              |
| ------------------------- | ------------------------ | ------------------- |
| vim で文字が入らない      | 挿入モードでない         | `i` → 入力 → Esc    |
| vim から抜けられない      | 終了コマンドが分からない | Esc → `:q!` → Enter |
| nano の `^X` が分からない | `^` が Ctrl だと知らない | 画面下の案内を見る  |
| emacs が GUI で開いた     | 端末用オプション不足     | `emacs -nw`         |

## まとめ

- 遠隔ではターミナルエディタが必要になる
- 入口は `nano`、保険として `vim` の保存・終了
- 手元の快適さと、サーバの緊急編集は分けて考えてよい
