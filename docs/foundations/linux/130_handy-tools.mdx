# 便利なツールたち

基本コマンドで一通り戦えるようになったあとに効く、**あると日々が楽になる道具** を紹介します。  
必須ではありません。環境に入っていないことも多いので、必要になったら入れてください（入れ方は OS / ディストリの案内に従います）。  
表示は環境や版で少し違います。意味が同じなら問題ありません。

:::tip[先に標準コマンド]

サーバによっては、追加ツールを入れられないことがあります。  
`ls` / `grep` / `find` / `ps` など、ここまでの標準コマンドが土台です。

:::

下の見出しは **ユースケース** です。開くと、基本的な使い方・実行例・読み方があります。

## 見る・移動する

<details>
<summary>ディレクトリの階層を一目で見たい → `tree`</summary>

`tree` は、ディレクトリ構造を木形式で表示するコマンドです。

**基本的な使い方:**

1. 見たいディレクトリを引数に付けて実行する（省略すると今いる場所）
2. 深すぎたら `-L 2` などで階層を制限する
3. 表示を眺めたら、そのまま次の作業へ（対話画面ではないので終了操作は不要）

```bash
tree ~/training-linux
```

例:

```text
/home/alex/training-linux
├── notes
│   ├── app.log
│   └── hello.txt
├── releases
│   ├── v1
│   └── v2
└── scripts
    └── hello.sh

4 directories, 3 files
```

読み方のポイント:

- `├──` / `└──` … 子エントリ。インデントが深いほど下の階層
- 末尾の `directories` / `files` … 件数の要約
- ディレクトリ名のあとに続く枝が、その中身

深さだけ見たいとき:

```bash
tree -L 2 ~/training-linux
```

`-L` は表示する階層の深さです。  
入っていない環境では `ls -R` でも代用できます。

</details>

<details>
<summary>作業ディレクトリを行き来したい → `pushd` / `popd`</summary>

`pushd` / `popd` は、ディレクトリの履歴（スタック）を使って移動するシェルの仕組みです。  
`cd` だと「さっきどこにいたか」を自分で覚える必要がありますが、スタックなら戻れます。

**基本的な使い方:**

1. いまの場所から、一時的に行きたい場所へ `pushd 行き先`
2. 向こうで作業する（`pwd` / `ls` など）
3. 戻るときは `popd`
4. 迷ったら `dirs` でスタックを見る

```bash
cd ~/training-linux
pushd /tmp
```

例:

```text
/tmp ~/training-linux
```

```bash
pwd
```

例:

```text
/tmp
```

```bash
popd
pwd
```

例:

```text
~/training-linux
/home/alex/training-linux
```

読み方のポイント:

- `pushd` の直後の 1 行 … スタックの中身。左がいまいる場所、右が覚えていた場所
- `popd` のあと … 覚えていた場所へ戻る。続けて `pwd` で現在地を確認すると安心
- `dirs` … スタックだけを再表示したいときに使う

同じ 2〜3 か所を往復する調査で特に便利です。

</details>

<details>
<summary>`ls` をもっと読みやすくしたい → `eza`</summary>

`eza` は、`ls` の代替として見やすさや情報量を強化したコマンドです（かつての `exa` の後継）。

**基本的な使い方:**

1. まず `eza` または `eza -la` で一覧を見る（`ls` / `ls -la` の置き換え）
2. 階層が欲しければ `eza --tree -L 2`
3. オプションを増やしすぎず、普段使う 1〜2 パターンに固定する

```bash
eza -la
```

例:

```text
drwxr-xr-x  - alex  3 Mar 10:00 notes
.rw-r--r-- 12 alex  3 Mar 10:06 notes/hello.txt
```

```bash
eza --tree -L 2
```

例:

```text
.
├── notes
│   ├── app.log
│   └── hello.txt
└── scripts
    └── hello.sh
```

読み方のポイント:

- `-la` … 隠しファイル込みの詳細。左の権限・所有者・更新時刻は `ls -l` と同じ見方
- `--tree` … `tree` に近い階層表示。`-L` で深さ制限
- 色や Git 列が出る版もあるが、まずは名前と種別（ディレクトリかファイルか）を追う

本番サーバに無いことも多いので、自分の開発端末向け、と考えるとよいです。

</details>

<details>
<summary>ファイルの中身を色付きで読みたい → `bat`（`cat` の代替）</summary>

`bat` は、構文ハイライトや行番号付きでファイルを表示するコマンドです。  
短いファイルの確認で `cat` の代わりに使うことが多いです。

**基本的な使い方:**

1. `bat ファイル` で開く
2. 1 画面に収まる短さなら、表示を見て終わり
3. 長いファイルではページャになる
   - 下へ … Space または ↓
   - 上へ … `b` または ↑（環境差あり）
   - 終了 … `q`
4. 色や装飾なしで素早く流したいときは `bat --paging=never ファイル`、または従来の `cat`

```bash
bat notes/app.log
```

例（イメージ。色は端末上で付きます）:

```text
───────┬────────────────────────
       │ File: notes/app.log
───────┼────────────────────────
   1   │ ERROR disk full
   2   │ INFO ok
   3   │ ERROR timeout
───────┴────────────────────────
```

読み方のポイント:

- 上部 … どのファイルを見ているか
- 左の数字 … 行番号
- 右 … 本文。言語や拡張子に応じて色が付くことが多い

素早く全部流したいだけのときは、従来どおり `cat` / `less` でも構いません。

</details>

## 探す

<details>
<summary>ファイル名で素早く探したい → `fd`（`find` の代替）</summary>

`fd` は、ファイル名検索に特化した `find` の代替コマンドです。  
デフォルトでわかりやすい結果になりやすく、入力も短く済みます。

**基本的な使い方:**

1. `fd キーワード` で、名前にキーワードを含むファイルを探す
2. 場所を絞るなら `fd キーワード ディレクトリ`
3. 拡張子だけ見たいなら `fd -e log`
4. 出たパスを、必要なら `bat` やエディタで開く

```bash
fd hello ~/training-linux
```

例:

```text
notes/hello.txt
scripts/hello.sh
```

```bash
fd -e log ~/training-linux
```

例:

```text
notes/app.log
notes/a.log
```

読み方のポイント:

- 1 行が 1 ヒット。パスがそのまま出る
- 引数だけ … 名前に含まれるパターンで検索
- `-e log` … 拡張子が `log` のものに限定

複雑な条件（更新日の細かい指定など）は、これまでどおり `find` が強いです。

</details>

<details>
<summary>中身の文字列を高速に探したい → `ripgrep`（`grep` の代替）</summary>

`ripgrep`（コマンド名は `rg`）は、ディレクトリを再帰的に・高速に文字列検索するコマンドです。  
コードやログの横断検索でよく使われます。

**基本的な使い方:**

1. `rg 検索語 ディレクトリ` で中身を探す（ディレクトリ省略時は今の場所）
2. 行番号が欲しければ `rg -n 検索語 ディレクトリ`
3. ヒットした `ファイル:行` を手がかりに、`bat` やエディタで開く
4. 何も出なければヒットなし

```bash
rg ERROR ~/training-linux/notes
```

例:

```text
notes/app.log:ERROR disk full
notes/app.log:ERROR timeout
```

```bash
rg -n ERROR ~/training-linux/notes
```

例:

```text
notes/app.log:1:ERROR disk full
notes/app.log:3:ERROR timeout
```

読み方のポイント:

- `ファイル:行内容` … どこにマッチしたか
- `-n` を付けると `ファイル:行番号:内容` になり、あとで開きやすい
- 何も出なければヒットなし（終了コードは非 0 になることがある）

サーバに無い場合は `grep -R` で同じ目的を果たせます。

</details>

<details>
<summary>候補をあいまい検索で選びたい → `fzf`</summary>

`fzf` は、一覧をインタラクティブに絞り込み選択するコマンドです。  
履歴やファイル一覧と組み合わせると効果が大きいです。

**基本的な使い方:**

1. 何かの一覧をパイプで渡す（例: `printf "a\nb\nc\n" | fzf`）
2. 画面が開いたら、絞り込みたい文字を打つ
3. ↑↓ で候補を移動する
4. Enter で決定（選んだ行が標準出力に出る）
5. やめるときは Esc または Ctrl+C

まずは次で操作感だけ掴むのがおすすめです。

```bash
printf "apple\nbanana\ncherry\n" | fzf
```

画面イメージ:

```text
> app
  apple
> banana
  cherry
```

読み方・操作のポイント:

- 下の一覧 … 候補。上部（または下部）の入力欄に文字を打つと絞り込まれる
- ハイライトされている行 … いま選んでいる候補
- Enter 後にシェルへ戻ると、選んだ 1 行だけが表示される

実務では次のようにパイプします。

```bash
fd --type f ~/training-linux | fzf
```

選んだパスが画面に出るので、コピーして `bat` に渡したり、次のように一続きにできます。

```bash
bat "$(fd --type f ~/training-linux | fzf)"
```

（キャンセルした場合はパスが空になる点に注意）

</details>

## プロセス・ポート

<details>
<summary>プロセスを対話的に監視したい → `htop`</summary>

`htop` は、プロセスを色付き・操作可能な画面で監視するコマンドです（[プロセス](./processes) の `top` の強化版イメージ）。

**基本的な使い方（見るだけ）:**

1. `htop` で起動する
2. 上部の CPU / Mem ゲージで、全体が忙しそうかを見る
3. 一覧を ↓↑ で動かし、`CPU%` や `MEM%` が高い行、`Command` の内容を確認する
4. 見終わったら **`q`** で終了する

これだけできれば、まずは十分です。

**もう少しだけ使うとき:**

| やりたいこと | 操作（よくある割り当て）                              |
| ------------ | ----------------------------------------------------- |
| 列で並べ替え | `F6`（または `>`）→ 列を選んで Enter                  |
| 名前で探す   | `F3` → 文字列を入力                                   |
| 表示を絞る   | `F4` → フィルタ文字列を入力（解除はまた `F4` で空に） |
| ツリー表示   | `F5`                                                  |
| 終了         | `q` または `F10`                                      |

画面下部にショートカット一覧が出ていることが多いです。  
迷ったらそこを見ます。

```bash
htop
```

画面イメージ（抜粋）:

```text
  CPU[|||||        12%]   Mem[|||||||| 1.2G/7.7G]
  PID USER      PRI  NI  VIRT   RES  CPU% MEM%   TIME+  Command
 1842 alex       20   0 10328  5120   0.0  0.1   0:00.12 bash
 2201 alex       20   0  2.1G 350M    5.0  4.4   1:12.03 node
  F1Help F2Setup F3Search F4Filter F5Tree F6Sort F9Kill F10Quit
```

読み方のポイント:

- 上部のゲージ … CPU / メモリのざっくり使用率
- `PID` … プロセス ID（別ターミナルで `kill` するときに使う）
- `CPU%` / `MEM%` … 負荷の目安。高い行から疑う
- `Command` … 何を実行しているか
- 最下部の `F3` / `F9` / `F10` など … その画面で使えるキー

:::warning[Kill は後回しでよい]

`F9` などでプロセスを止められますが、最初は使わなくて構いません。  
止めるなら PID を控えて別ターミナルで確認してから、[プロセス](./processes) の `kill` の考え方に従う方が安全です。

:::

入っていない場合は `top` や `ps` で足ります。  
`top` も終了は `q` です。

</details>

<details>
<summary>ポートやファイルを使っているプロセスを特定したい → `lsof` / `ss`</summary>

`lsof` は、「どのプロセスがどのファイル／ソケットを開いているか」を調べるコマンドです。  
ポート調査でもよく使います。

**基本的な使い方:**

1. ポートを調べる: `lsof -i :8080`（番号は対象に合わせる）
2. ファイルを調べる: `lsof /path/to/file`
3. 出た `COMMAND` と `PID` を控える
4. 待ち受け一覧が欲しければ `ss -tlnp` を見る

```bash
lsof -i :22
```

例:

```text
COMMAND  PID USER   FD   TYPE DEVICE SIZE/OFF NODE NAME
sshd     812 root    3u  IPv4  12345      0t0  TCP *:ssh (LISTEN)
```

読み方のポイント:

- `COMMAND` / `PID` … どのプロセスか
- `NAME` の `*:ssh (LISTEN)` … 22 番相当を待ち受けている、という意味合い
- 何も出なければ、その条件で開いているものが見つからない

```bash
lsof /home/alex/training-linux/notes/app.log
```

例:

```text
COMMAND  PID USER   FD   TYPE DEVICE SIZE/OFF NODE NAME
tail    2301 alex    3r   REG  259,2     128  ... notes/app.log
```

`tail -f` などで掴んでいるプロセスが分かります。

待ち受けポートの一覧だけなら、新しい環境では `ss` が分かりやすいことも多いです。

```bash
ss -tlnp
```

例:

```text
State  Recv-Q Send-Q Local Address:Port  Peer Address:Port Process
LISTEN 0      128          0.0.0.0:22         0.0.0.0:*     users:(("sshd",pid=812,fd=3))
LISTEN 0      511          0.0.0.0:8080       0.0.0.0:*     users:(("node",pid=2201,fd=20))
```

読み方のポイント:

- `LISTEN` … 待ち受け中
- `Local Address:Port` … どのポートで待っているか（`:22` や `:8080`）
- `Process` … プロセス名と PID（権限不足だと空欄のことも）

:::tip[切り分け]

- 「このポートは誰？」 … `lsof -i :ポート` または `ss -tlnp`
- 「このファイルは誰が掴んでる？」 … `lsof パス`

:::

</details>

## 流す・加工する

<details>
<summary>見ながら結果もファイルに残したい → `tee`</summary>

`tee` は、標準入力を画面に出しつつファイルにも書くコマンドです。  
[パイプとリダイレクト](./pipes-and-redirect) でも扱いました。

**基本的な使い方:**

1. いつものパイプの末尾に `| tee 保存先` を付ける
2. 画面で結果を確認する
3. 同じ内容が保存先ファイルにも入っているかを `cat` で確認する
4. 追記したいときだけ `tee -a`

```bash
grep ERROR notes/app.log | tee notes/errors.txt
```

例（画面に出る内容）:

```text
ERROR disk full
ERROR timeout
```

```bash
cat notes/errors.txt
```

例:

```text
ERROR disk full
ERROR timeout
```

読み方のポイント:

- 画面に出た行 … いま見ている結果そのもの
- `notes/errors.txt` … 同じ内容の控え。あとから共有や再分析に使える
- 追記したいときは `tee -a`

</details>

<details>
<summary>JSON を扱いたい → `jq`</summary>

`jq` は、JSON をフィルタ・整形するコマンドです。  
API レスポンスや設定ファイルの確認で頻出します。

**基本的な使い方:**

1. まず `... | jq .` で整形して全体を見る
2. 1 つの値が欲しければ `jq -r .キー名`
3. ファイルなら `jq . file.json` または `jq -r .name file.json`
4. エラーなら、入力が JSON として正しいかを疑う

```bash
echo '{"name":"alex","role":"dev"}' | jq .
```

例:

```text
{
  "name": "alex",
  "role": "dev"
}
```

```bash
echo '{"name":"alex","role":"dev"}' | jq -r .name
```

例:

```text
alex
```

読み方のポイント:

- `jq .` … 整形された JSON 全体。キーと値が対で並ぶ
- `jq -r .name` … `name` の値だけ。`-r` は引用符を外す（スクリプトで使いやすい）
- エラーになるときは、入力が JSON として壊れていないかを疑う

入れ子の JSON も、パスを指定して抜けます。  
巨大 JSON では、先にファイルへ保存してから `jq` すると安全です。

</details>

## スクリプト・対話

<details>
<summary>スクリプトに簡単な対話 UI を足したい → `gum`</summary>

`gum` は、シェルスクリプト向けの入力・選択・スピナーなどを提供するコマンド群です（Charm 製）。  
確認プロンプトや選択リストを短く書けます。

**基本的な使い方:**

1. 確認: `gum confirm "メッセージ"`
   - 左右または Tab で Yes/No を選ぶ
   - Enter で決定
   - Yes なら終了コード 0（`&&` の右側が動く）
2. 選択: `gum choose "a" "b" "c"`
   - ↑↓ で選んで Enter
   - 選んだ文字列が標準出力に出る
3. 入力: `gum input --placeholder "username"`
   - 打ち込んで Enter
   - 入力した文字列が標準出力に出る
4. やめるときは Ctrl+C

```bash
gum confirm "Deploy to staging?" && echo "deploying"
```

画面イメージ:

```text
Deploy to staging?
  Yes / No
```

`Yes` を選ぶと:

```text
deploying
```

```bash
gum choose "dev" "stg" "prod"
```

画面で `stg` を選んだときの出力例:

```text
stg
```

読み方のポイント:

- 画面上の選択結果が、そのまま標準出力に出る
- `&&` の右側は、確認が成功（Yes）したときだけ動く
- 無人 CI では対話が止まるので、引数で渡す設計の方が向く

</details>

<details>
<summary>対話プロンプトを自動化したい → `expect`</summary>

`expect` は、「出てきた文言を待ち、応答を送る」ことを自動化するツールです。  
古い機器や、どうしても対話が必要な手順の橋渡しに使われることがあります。

**基本的な考え方（まず覚える型）:**

1. `spawn` で対話コマンドを起動する
2. `expect "待たい文字列"` で画面出力を待つ
3. `send "送る文字\n"` で応答する（末尾の `\n` が Enter 相当）
4. 必要なだけ 2〜3 を繰り返す
5. 最後は `expect eof` や `exit` 送付で終了する

手元で安全に触るなら、パスワードが不要な対話（例: 簡単な自作スクリプト）で型だけ練習するのがおすすめです。

概念だけの例:

```bash
expect << 'EOF'
spawn ssh alex@203.0.113.10
expect "password:"
send "REDACTED\n"
expect "$ "
send "pwd\n"
expect "$ "
send "exit\n"
expect eof
EOF
```

動きのイメージ:

```text
spawn ssh alex@203.0.113.10
alex@203.0.113.10's password:
alex@app-server:~$ pwd
/home/alex
alex@app-server:~$ exit
```

読み方のポイント:

- `spawn` … 起動したコマンドの出力が流れ始める
- `expect "…"` … その文字列が来るまで待つ
- `send` … 待ったあとに送るキー入力
- 実際のプロンプト表記は環境で違うので、待つ文字列は合わせて調整する

:::warning[パスワードをスクリプトに直書きしない]

上記は形式の説明用です。  
秘密をファイルに埋め込む運用は避け、鍵認証や公式の秘密管理に寄せてください。  
`expect` は強力なぶん、扱いを誤ると危険です。

:::

</details>

## ファイル・画像のひと手間

<details>
<summary>zip にパスワードをかけたい → `zipcloak`</summary>

`zipcloak` は、既存の zip アーカイブにパスワード保護を付けるコマンドです。

**基本的な使い方:**

1. 先に通常どおり `zip 出力.zip 入れたいファイル` で zip を作る
2. `zipcloak その.zip` を実行する
3. パスワードを 2 回入力する
4. 受け渡し先では、同じパスワードで展開する

```bash
zip notes.zip notes/hello.txt
```

例:

```text
  adding: notes/hello.txt (stored 0%)
```

```bash
zipcloak notes.zip
```

例:

```text
Enter password:
Verify password:
encrypting: notes/hello.txt
```

読み方のポイント:

- 最初の `zip` … アーカイブ作成。`adding:` が出ればファイルが入れられた
- `zipcloak` … 既存 zip にパスワードを付ける。二重入力を求められたら同じ文字列を入れる
- 解除や展開時にも同じパスワードが必要

受け渡しの一時保護には使えますが、現代的な暗号化の第一候補というより、zip 連携が必要なときの道具、と捉えてください。

</details>

<details>
<summary>PNG を軽くしたい → `pngquant`</summary>

`pngquant` は、PNG 画像を品質とのバランスを取りながら圧縮するコマンドです。  
スライドや Web 用アセットのサイズ削減で使われます。

**基本的な使い方:**

1. 元画像を残すため、必ず `-o 出力先` を付ける
2. `pngquant --quality=65-80 元.png -o 小.png` を実行する
3. `ls -l` でサイズを比較する
4. 画像を開いて、画質が許容範囲か目視する

```bash
pngquant --quality=65-80 image.png -o image-small.png
ls -l image.png image-small.png
```

例:

```text
-rw-r--r-- 1 alex alex 420000 Mar 3 12:00 image.png
-rw-r--r-- 1 alex alex  98000 Mar 3 12:00 image-small.png
```

読み方のポイント:

- サイズ列（例では `420000` → `98000`）が小さくなっていれば圧縮できている
- `-o` … 出力先。元ファイルを残せる
- 画質が許容範囲かは、必ず目視確認する

可逆が必須な画像では、別手段を検討してください。

</details>

## 調べもの・ディスク

<details>
<summary>コマンドの短い実例が欲しい → `tldr`</summary>

`tldr` は、マンページより短い実例中心のヘルプを表示するコマンドです。

**基本的な使い方:**

1. `tldr コマンド名` を実行する
2. 近い用途の実例を見つける
3. そのコマンドをコピーして試し、詳細が必要なら `man コマンド名` へ進む

```bash
tldr tar
```

例（抜粋・イメージ）:

```text
tar

Archiving utility.

- Create an archive from files:
  tar cf target.tar file1 file2

- Extract an archive:
  tar xf source.tar
```

読み方のポイント:

- 先頭 … コマンドの一言説明
- `-` で始まる箇条書き … よくある用途
- インデントされた行 … そのまま試せる実例コマンド

正式な詳細は `man` も併用してください。

</details>

<details>
<summary>何がディスクを食っているか見たい → `ncdu`</summary>

`ncdu` は、ディレクトリサイズを対話的に眺めるコマンドです。  
`du` の結果を歩きながら絞り込むイメージです。

**基本的な使い方:**

1. `ncdu 調べたいディレクトリ` で起動する（初回はスキャンに少し時間がかかることがある）
2. ↓↑ で行を移動する
3. 大きなディレクトリで Enter（または →）して中に入る
4. 戻るときは ← または Backspace（環境差あり）
5. 見終わったら **`q`** で終了する

最初は削除操作を使わず、「どこが大きいか見る」だけにすると安全です。

```bash
ncdu ~/training-linux
```

画面イメージ:

```text
ncdu 1.19 ~ Use the arrow keys to navigate, press ? for help
--- /home/alex/training-linux ------
  48.0 KiB [##########] /notes
  16.0 KiB [###       ] /scripts
   4.0 KiB [#         ] /releases
```

読み方のポイント:

- 左のサイズ … その配下のおおよそ合計
- バーが長い行 … 相対的に大きいディレクトリ
- 画面上部のパス … いま見ている場所
- `?` … ヘルプ（キー一覧）。迷ったら開く

無い場合は `du -sh *` から始めれば足ります（[実務での使い方](./daily-ops)）。

</details>

## 入れ方の考え方

パッケージ名はディストリで違うことがあります。  
手元の開発環境なら、公式ドキュメントやパッケージマネージャの検索（`apt search`、`brew search` など）で探すのが早いです。  
共有サーバでは、無断インストールせずルールを確認してください。
