# Linux / Shell をはじめよう

この章では、サーバや開発環境の土台になる **Linux** と、その上で話す言葉である **シェル** を学びます。  
クラウドもコンテナも CI も、最後はだいたい「端末でコマンドを打つ世界」に着地します。  
ここが弱いと、どの技術を学んでも「画面の奥で何が起きているか」が見えにくいままになります。

## この章で分かること

- Linux とシェルが、なぜほぼすべての技術の前提になるか
- パス・ファイル操作・検索・パイプといった日常の操作
- ターミナル上でのテキスト編集（nano / vim など）
- 権限・プロセス・環境変数など、トラブルシュートに効く見方
- テキスト加工と短いシェルスクリプトで、繰り返し作業を楽にする方法
- あると便利な追加ツールの使いどころ

## こんな場面で効く

アプリのログを見たいのに、どのディレクトリにいるか分からない。  
`Permission denied` と出ても、何を直せばいいか見当がつかない。  
同じ確認コマンドを毎日手で打ち続けて、打ち間違いで調査が長引く。

GUI だけで済ませているうちは気になりにくいですが、サーバやコンテナに入った瞬間、これらのつまずきが一気に表面化します。  
シェルが使えると次が楽になります。

- **いまどこにいて、何があるか** を自分で確認できる
- ログや設定を、探し・絞り・並べ替えて原因に近づける
- 「動かない」の正体（権限、パス、プロセス、環境）を切り分けられる

目的はコマンドの暗記ではなく、**自分がいる環境を読み、安全に操作する感覚** を身につけることです。

:::tip[この章のゴール]

端末で現在地を把握し、ファイルとプロセスを扱い、問題の切り分けと小さな自動化まで自力で進められる状態を目指します。

:::

## 手を動かす環境について

この章のコマンドは、**bash 互換** の書き方を想定しています（bash / 多くの zsh）。  
fish を使っている場合も、外部コマンドの操作自体は追えますが、スクリプト例はそのまま動かないことがあります。  
シェルの違いは [Linux とシェルの考え方](./concepts) を参照してください。  
次のような環境なら追えます。

- リモートの Linux サーバ（[SSH](../remote-access/ssh) で入る）
- 自分の PC 上の Linux
- Windows 上の WSL（Ubuntu など）。くわしくは [Windows で Linux コマンドを使う](./windows-linux-commands)
- macOS のターミナル（多くの操作は近い。違う点はその都度補足します）

<details>
<summary>Windows のコマンドプロンプトや PowerShell だけで十分？</summary>

Windows 固有のシェルでも開発はできます。  
ただしクラウド上の Linux サーバ、コンテナ、多くの CI は Linux 前提です。  
この章を追うなら [WSL や Git Bash](./windows-linux-commands) の方が近道です。

</details>
