# プロセス

アプリが重い、止まっているように見える、同じ処理が二重に動いていそう。  
こういうとき必要になるのが **プロセス**（動いているプログラムの実体）の見方です。

## このページで分かること

- プロセスと PID の意味
- `ps` で一覧を見る
- 止め方の基本と、強制終了の注意

## なぜプロセスを見るか

「サーバが応答しない」は、サーバ全体が死んでいるとは限りません。  
特定のプロセスだけが固まり、CPU やメモリを占有していることも多いです。  
GUI のタスクマネージャに相当する情報を、シェルから取る感覚を持ちます。

## 自分のシェルもプロセス

`ps` は、動いているプロセスの一覧を表示するコマンドです。

```bash
ps
```

例:

```text
  PID TTY          TIME CMD
 1842 pts/0    00:00:00 bash
 1901 pts/0    00:00:00 ps
```

- `PID` … プロセス ID（プロセスの識別番号）
- `CMD` … 何を実行しているか

いまのシェル（例では `bash`）も、ひとつのプロセスとして見えます。

## もう少し広く見る

```bash
ps aux | head -n 5
```

例（環境で大きく違います）:

```text
USER       PID %CPU %MEM    VSZ   RSS TTY      STAT START   TIME COMMAND
root         1  0.0  0.1 167948 11456 ?        Ss   Mar01   0:03 /sbin/init
alex      1842  0.0  0.0  10328  5120 pts/0    Ss   10:00   0:00 bash
alex      1920  0.0  0.0  11456  3584 pts/0    R+   10:05   0:00 ps aux
```

読み方の入口:

- `USER` … 実行ユーザー
- `PID` … プロセス ID
- `%CPU` / `%MEM` … 使用率の目安
- `COMMAND` … 起動コマンド

`head` で先頭だけ見ています。  
実調査では `grep` と組み合わせることが多いです。

```bash
ps aux | grep bash
```

:::tip[切り分けの入口]

「そのアプリのプロセスがあるか」「CPU を食っていないか」「起動コマンドは想定どおりか」  
この三点が見えるだけでも、調査の解像度が上がります。

:::

<details>
<summary>`top` / `htop`（対話的な監視）</summary>

`top` は、プロセスの状態を画面上で継続的に更新表示するコマンドです。

```bash
top
```

終了は `q` です。  
入っている環境では `htop`（見やすい対話型の類似ツール）の方が使いやすいこともあります。  
まずは `ps` で十分です。

</details>

## バックグラウンドとジョブ（入口）

長いコマンドを走らせつつ、同じ端末で別作業をしたいことがあります。

```bash
sleep 30 &
jobs
```

例:

```text
[1]+  Running                 sleep 30 &
```

- `sleep` … 指定秒数だけ待つコマンド（ここでは動作確認用）
- 末尾の `&` … 背景で実行
- `jobs` … この端末のジョブ一覧を表示する

<details>
<summary>`fg` / `Ctrl+C` / `Ctrl+Z`</summary>

- `fg` … 背景のジョブを前景に戻すコマンド
- Ctrl+C … 前景のプロセスに中断を送る（よく使う）
- Ctrl+Z … 一時停止（その後 `bg` で背景再開や `fg`）

最初は「Ctrl+C で止める」「`&` で背景」くらいでも実務に入れます。

</details>

## プロセスを止める：`kill`

`kill` は、指定したプロセスに終了などの信号を送るコマンドです。

```bash
sleep 60 &
jobs
```

表示された PID を指定して止めます（番号は環境で違います）。

```bash
kill 1933
```

成功時は何も出ないことが多いです。  
`ps` や `jobs` で消えていれば止まっています。

既定の `kill` は「終了してほしい」という信号（TERM）を送ります。  
それでも終わらないときだけ、より強い手段を検討します。

```bash
kill -9 1933
```

:::warning[`kill -9` は最後の手段]

`-9`（KILL）は、相手に片付けの暇を与えず強制終了します。  
データ整合性が崩れることがあるので、通常の `kill` で終わらないとき・影響を理解してから使います。  
他人のプロセスや本番の重要プロセスには、特に慎重に。

:::

## よくあるつまずき

| 症状                    | よくある原因              | 方向性                                       |
| ----------------------- | ------------------------- | -------------------------------------------- |
| `kill` できない         | 他人のプロセス / 権限不足 | オーナーと権限を確認                         |
| `grep` に自分自身が映る | `grep` 行もマッチする     | パターンの工夫、または PID を目で確認        |
| 止めたのにまたいる      | 別 PID で再起動している   | 起動元（サービス管理）を疑う。詳細は環境依存 |

## まとめ

- プロセスは動いているプログラム、PID で識別する
- 一覧は `ps`（必要なら `top`）
- 停止はまず通常の `kill`、強制は慎重に
