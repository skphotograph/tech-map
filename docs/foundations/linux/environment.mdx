# 環境変数と PATH

`command not found` と出たとき、ソフトウェアが未インストールとは限りません。  
「入っているのに、シェルが探しに行く場所」がずれていることも多いです。  
その鍵が **環境変数**、特に `PATH` です。

## このページで分かること

- 環境変数とは何か
- `PATH` がコマンド解決にどう効くか
- `export` と、設定の永続化の入口

## なぜ環境変数が必要か

プログラムは、実行時に「どの設定ファイルを読むか」「どこにログを書くか」「どの言語ランタイムを使うか」を決める必要があります。  
それを毎回引数で渡すのは大変なので、シェルの環境に名前付きの値として持たせます。

## 見てみよう

```bash
echo "$HOME"
```

例:

```text
/home/alex
```

`HOME` はホームディレクトリを指す代表的な環境変数です。  
`$` を付けて値を参照します（`echo` は文字列を出力するコマンドです）。

```bash
env | head -n 10
```

`env` は、今の環境に見える変数の一覧を出すコマンドです（件数が多いので `head` で先頭だけ）。

特定の名前だけ見る:

```bash
printenv PATH
```

`printenv` は、指定した環境変数の値を表示するコマンドです。

例（実際の値は環境で大きく違います）:

```text
/usr/local/bin:/usr/bin:/bin
```

## `PATH` が効く仕組み

シェルは、`ls` や `git` のようなコマンド名だけを見つけるとき、`PATH` に並んだディレクトリを順に探します。

```mermaid
flowchart LR
  name[打ったコマンド名]
  pathVar[PATH の各ディレクトリ]
  execFile[実行ファイル]
  name --> pathVar --> execFile
```

区切りは `:` です。  
左にあるディレクトリが優先されます。

```bash
which ls
```

例:

```text
/usr/bin/ls
```

`which` は、いまの `PATH` で解決される実行ファイルの場所を示します。

:::tip[`command not found` の見方]

1. 本当に入れているか  
2. `which コマンド名` で見つかるか  
3. `echo "$PATH"` に、入っている場所が含まれているか  

この順で見ると、インストール問題と PATH 問題を切り分けやすいです。

:::

<details>
<summary>`type` も便利</summary>

`type` は、コマンド名が実行ファイル・エイリアス・シェル関数のどれかを示すコマンドです。

```bash
type ls
```

例:

```text
ls is /usr/bin/ls
```

調査向きです。

</details>

## 一時的に変数を置く

`export` は、環境変数を設定して子プロセスにも渡すコマンドです。

```bash
export APP_ENV=dev
echo "$APP_ENV"
```

例:

```text
dev
```

アプリの設定を環境変数で読む方式は実務でよく出ます。

:::info[閉じると消える]

この方法で入れた値は、基本的に **今のシェルセッション限り** です。  
端末を閉じると消えます。

:::

## 永続化の入口

ログインのたびに読み込まれる設定ファイルに書きます。  
代表例:

- bash … `~/.bashrc` や `~/.profile`（ディストリで差あり）
- zsh … `~/.zshrc`

例（概念）:

```bash
export PATH="$HOME/bin:$PATH"
```

自分用の実行ファイル置き場を、既存の `PATH` の前に足す書き方です。

:::warning[設定ファイルは慎重に]

文法を壊すと、シェル起動そのものが不便になることがあります。  
編集前にコピーを取り、1 行ずつ足して動作確認するのが安全です。  
本番サーバの共有設定を独断で変えないでください。

:::

<details>
<summary>履歴 `history` の入口</summary>

`history` は、このシェルで打ったコマンドの履歴を表示するコマンドです。

```bash
history | tail -n 20
```

最近の操作の復習に使えます。  
機密（トークンやパスワード）をコマンドラインに直書きすると履歴に残ることがあるので、秘密情報は引数にしないでください。

</details>

## よくあるつまずき

| 症状 | よくある原因 | 方向性 |
| --- | --- | --- |
| `command not found` | 未インストール / PATH 外 | `which` と `echo "$PATH"` |
| 変数が空 | `$` の付け忘れ / 別シェルで設定した | `echo "$NAME"` で確認 |
| 設定したのに効かない | 永続化ファイルを読み込んでいない | 新しい端末を開く、または `source` で再読込 |

<details>
<summary>`source` で再読込</summary>

`source` は、設定ファイルなどを今のシェル上で読み込んで実行するコマンドです。

```bash
source ~/.bashrc
```

編集した設定を、今のシェルにすぐ反映したいときに使います。  
ファイル名は使っているシェルに合わせてください。

</details>

## まとめ

- 環境変数は、プロセスに渡る名前付きの設定
- `PATH` はコマンド検索パス。`which` で解決先を確認できる
- `export` はセッション限り、永続化は設定ファイルへ
