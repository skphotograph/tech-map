# シンボリックリンク

ファイル操作と [ターミナルでの編集](./terminal-editors) の入口が分かったら、次に押さえておきたいのが **シンボリックリンク**（symlink / ソフトリンク）です。  
設定の「いま使っている版」、コマンドの実体、デプロイ後の切り替えなど、現場ではほぼ必ず出会います。

## このページで分かること

- シンボリックリンクが解決する課題
- `ln -s` での作り方と、`ls -l` での見分け方
- 絶対パスと相対パスのリンク、切れたリンクの扱い
- ハードリンクとの違い（入口）

## なぜ必要か

同じアプリの設定を `config.v1` と `config.v2` で用意して、「本番がどっちを見ているか」が分からなくなる。  
デプロイのたびに長いパスを書き換えるのが怖くて、ミスる。

こういうときに使うのがシンボリックリンクです。  
**別名の入口** を置き、実体（本体のファイルやディレクトリ）を差し替えられるようにします。

うれしい点:

- 「いま有効なもの」を短い名前で固定できる（例: `current` → 実体のディレクトリ）
- 実体を動かさずに、参照だけ切り替えられる
- 複数の場所から同じ実体を参照できる

:::tip[イメージ]

ショートカットに近いですが、OS 上の正式な仕組みです。  
多くのプログラムは、リンク経由でも「そのパスにあるもの」として扱います。

:::

## 作ってみる：`ln -s`

[ファイルとディレクトリ](./files-and-directories) の練習用ディレクトリで進めます。

```bash
cd ~/training-linux
mkdir -p releases/v1 releases/v2
echo "version 1" > releases/v1/app.txt
echo "version 2" > releases/v2/app.txt
ln -s releases/v1 current
ls -l
```

例:

```text
lrwxrwxrwx 1 alex alex 11 Mar 3 11:00 current -> releases/v1
drwxr-xr-x 4 alex alex 4096 Mar 3 11:00 releases
```

`ln` はリンクを作るコマンドです。  
`-s` を付けると **シンボリックリンク** になります。

読み方のポイント:

- 先頭が `l` … シンボリックリンク
- `current -> releases/v1` … `current` という名前が、`releases/v1` を指している

中身は実体と同じように読めます。

```bash
cat current/app.txt
```

例:

```text
version 1
```

切り替えは、リンクを作り直す（または差し替える）イメージです。

```bash
ln -sfn releases/v2 current
cat current/app.txt
```

例:

```text
version 2
```

- `-f` … 既存のリンクがあっても作る（差し替え）
- `-n` … リンク自体を対象として扱う（ディレクトリリンクの取り違え防止に使うことが多い）

:::warning[本番の差し替えは手順を確認]

`-sfn` は便利ですが、共有サーバでは運用ルールがあることがあります。  
練習以外では、対象パスと影響を確認してから使ってください。

:::

## `ls -l` で見分ける

通常ファイルは `-`、ディレクトリは `d`、シンボリックリンクは `l` です。  
[権限](./permissions) の読み方とセットで覚えると、調査が速くなります。

```bash
ls -l current
```

例:

```text
lrwxrwxrwx 1 alex alex 11 Mar 3 11:00 current -> releases/v2
```

権限表示が `rwxrwxrwx` に見えても、**実際にできる操作は実体側の権限** に依存します。  
リンク自体の表示だけで判断しないでください。

## 絶対パスと相対パス

リンク先は、絶対パスでも相対パスでも書けます。

```bash
# 相対（いまのディレクトリからの道順）
ln -s releases/v1 current-rel

# 絶対（ルートからのフルパス）
ln -s "$(pwd)/releases/v1" current-abs
ls -l current-rel current-abs
```

| 種類 | 特徴                                                             |
| ---- | ---------------------------------------------------------------- |
| 相対 | ディレクトリごと移しても、相対関係が保てば切れにくいことがある   |
| 絶対 | 「どこから見ても同じ実体」と明示しやすい。実体を移すと切れやすい |

:::info[どちらを使うか]

プロジェクト内の配置をセットで動かすなら相対が向くことが多いです。  
システム全体の定位置（例: `/etc/...`）を指すなら絶対が分かりやすいです。  
チームの既存ルールに合わせるのが先です。

:::

## 切れたリンク（dangling）

実体を消したり、パスを間違えたりすると、リンクだけが残って指先がなくなります。

```bash
ln -s releases/missing broken
ls -l broken
cat broken
```

例（`cat` の失敗）:

```text
cat: broken: No such file or directory
```

`ls -l` では矢印先が見えても、実体が無いことがあります。  
「ファイルがあるように見えるのに開けない」ときは、リンク切れを疑います。

<details>
<summary>リンク先の確認：`readlink` / `realpath`</summary>

```bash
readlink current
```

例:

```text
releases/v2
```

`readlink` は、シンボリックリンクが指すパスを表示するコマンドです。

```bash
realpath current
```

例:

```text
/home/alex/training-linux/releases/v2
```

`realpath` は、リンクをたどった先の実パスを求めるコマンドです（環境に入っていないこともあります）。

</details>

## 消すとき何が消えるか

```bash
rm current
ls releases/v2
```

`rm` で消えるのは **リンクという名前** であり、通常は実体ディレクトリまで消えません。  
実体を消したいときは、実体のパスを指定します。

:::tip[消す前の確認]

リンクを消すつもりが実体を消していないか、逆に実体を消すつもりが無いか。  
`ls -l` で `->` の有無を見てから `rm` すると事故が減ります。

:::

## ハードリンクとの違い（入口）

同じ「リンク」という言葉でも、次は別物です。

|              | シンボリックリンク（ソフト）       | ハードリンク                     |
| ------------ | ---------------------------------- | -------------------------------- |
| 作り方       | `ln -s`                            | `ln`（`-s` なし）                |
| 実体との関係 | パス名を覚えている近道             | 同じ実体を別の名前で指す         |
| ディレクトリ | 一般ユーザーでも作りやすい         | 通常はファイル向け（制約が多い） |
| よく使う場面 | 設定の切替、バージョンの `current` | この教材の範囲外でも困りにくい   |

この章で必須なのはシンボリックリンク側です。  
ハードリンクは、「別名だが同じ中身のファイル」という別概念、とだけ覚えておけば足ります。

<details>
<summary>ハードリンクを触るとき（参考）</summary>

```bash
echo "same" > notes/original.txt
ln notes/original.txt notes/also.txt
```

片方を編集すると、もう片方にも反映されます（同じ実体のため）。  
一方を `rm` しても、もう片方と実体が残ることがあります。  
日常の調査では、まずシンボリックリンク（`l` と `->`）を読めることが優先です。

</details>

## よくあるつまずき

| 症状                        | よくある原因                              | 方向性                                  |
| --------------------------- | ----------------------------------------- | --------------------------------------- |
| `No such file or directory` | リンク切れ / 相対パスの基準位置の取り違え | `ls -l` と `readlink`、`pwd`            |
| 意図しない実体を見ている    | 古い `current` のまま                     | `ls -l current` で矢印先を確認          |
| 権限エラー                  | リンクではなく実体側の権限                | 実体を `ls -l` で見る                   |
| `ln: File exists`           | 同名が既にある                            | 別名にするか、運用を理解したうえで `-f` |

## ミニ演習

1. `releases/v1` と `releases/v2` を用意する（このページの例で可）
2. `current` を `v1` 向きに作り、`cat current/app.txt` で確認する
3. `current` を `v2` 向きに差し替え、再度確認する
4. わざと切れたリンクを作り、`ls -l` と `cat` の違いを見る

## まとめ

- シンボリックリンクは「実体への近道」。切替と共有参照に強い
- 作成は `ln -s`、確認は `ls -l` の `l` と `->`
- 消すのはリンク名。切れリンクと実体の権限に注意
