# Git をはじめよう

この章では、チームでコードや設定を安全に共有・変更するための道具 **Git** を学びます。  
「なぜ必要か」から入り、自分の PC で履歴を残し、最後は GitHub 上で仲間とやり取りできるところまで進めます。

## この章で分かること

- Git が解決する課題（上書き事故、誰がいつ変えたか分からない問題）
- コミット・ブランチ・リモートといった基本の考え方
- 日常で使うコマンドの流れ
- よくある失敗からの戻り方（安全側のやり方）

## こんな場面で効く

開発をしていると、  
「この設定ファイル、先週誰かが直したはずなんだけど……反映されない。  
もしかして、このファイルは最新ではない？」  
となることがあります。  
それを避けるために `設定_最終.xlsx`、`設定_最終_20261001.xlsx` とその場限りの目印をつけた結果、あとから余計にどれが最新なのか分からなくなり、デグレードや先祖返りが起きる。  
一度は、こんな悪い例を見たことがあるのではないでしょうか。  
そこで Git の出番です。  
Git を使うと次が楽になります。

- **いつ・誰が・何を変えたか** を履歴として残せる
- 壊れるかもしれない変更を、本番用の線（後述の main）から切り離して試せる
- レビューしてもらってから、共有の場所へ取り込むことをルールとして強制できる

目的は「バージョン管理ツールを暗記すること」ではなく、**一緒に仕事を進めるための共通ルール** を身につけることです。
