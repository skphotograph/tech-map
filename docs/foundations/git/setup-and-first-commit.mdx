# 最初のコミットまで

コマンドの暗記から入ると、途中で「いま何をしているのか」が分からなくなりがちです。  
このページでは、Git を入れて初期設定し、小さなリポジトリで **最初のコミット** を作ります。  
前ページの [考え方](./concepts) を、手を動かすところまで落とす回です。  
「履歴が残る」感覚は、一度自分でコミットを見て初めて腹落ちします。  
ここを越えれば、あとの操作はずいぶん追いやすくなります。

## このページで分かること

- Git が入っているかの確認
- 名前とメールの初期設定（コミット作者として残る情報）
- リポジトリの作成から、1 回目のコミットまで

## 事前確認：Git が入っているか

ターミナル（コマンドプロンプト、PowerShell、macOS / Linux の端末など）で次を実行します。

```bash
git --version
```

例:

```text
git version 2.45.1
```

`git version` のあとに数字が出ていれば、Git が使える状態です。  
末尾の番号は環境によって違います。  
入っていない場合は、公式の [Git ダウンロード](https://git-scm.com/downloads) から、使っている OS 向けを入れてください。

<details>
<summary>バージョンはいくつなら十分？</summary>

この教材の内容は、おおむね Git 2.x 系で問題なく追えます。  
利用している環境でバージョンが古い場合は、その環境の導入手順に合わせてください。  
ここでは特定の組織向け手順には触れません。

</details>

## 最初に一度だけ：自分の名前とメール

コミットには「誰が記録したか」が残ります。  
次を自分の情報に置き換えて実行します。

```bash
git config --global user.name "Your Name"
git config --global user.email "you@example.com"
```

成功時は何も表示されないことが多いです。  
エラーが出なければ設定できています。

- `--global` … この PC のユーザー全体に効く設定
- メールは GitHub などに登録しているものと揃えると、あとで作者表示がつながりやすいです

設定の確認:

```bash
git config --global --list
```

例:

```text
user.name=Your Name
user.email=you@example.com
```

`user.name` と `user.email` に、いま入れた値が並んでいれば OK です。  
ほかの行が出ることもありますが、まずはこの 2 つを確認します。

<details>
<summary>メールを公開したくないとき</summary>

GitHub を使う場合、GitHub が用意する「noreply」形式のメールを使う方法があります。  
GitHub の設定画面（メール関連）に案内があるので、必要ならそちらを使ってください。  
サンプルに実在の個人メールを書かないよう注意しましょう。

</details>

## 練習用フォルダを作る

ホーム直下など、好きな場所で練習用ディレクトリを作ります。

```bash
mkdir task-board-notes
cd task-board-notes
```

`mkdir` はフォルダ作成、`cd` はその中へ移動するコマンドです。  
成功時は通常メッセージが出ません。  
プロンプトの場所が `task-board-notes` に変わっていれば移動できています。

ここからは、架空のプロジェクト `task-board` のメモ置き場、という設定で進めます。

## リポジトリを初期化する

```bash
git init
```

例:

```text
Initialized empty Git repository in /Users/you/task-board-notes/.git/
```

「空の Git リポジトリを初期化した」という意味です。  
末尾の `.git/` が、履歴の置き場です（[考え方](./concepts)）。

状態を見てみます。

```bash
git status
```

例:

```text
On branch main

No commits yet

nothing to commit (create/copy files and use "git add" to track)
```

読み方のポイント:

- `On branch main` … いま `main` ブランチにいる
- `No commits yet` … まだコミットがない
- 下の一文 … 追跡するファイルがまだない、という案内

表示の文言は Git の版で少し違います。  
意味が同じなら問題ありません。  
`git status` はこれから一番使う確認コマンドです。  
迷ったらまずこれ、で大丈夫です。

## ファイルを作って、ステージに乗せる

メモファイルを作ります。  
中身は何でも構いません。

```bash
echo "# task-board notes" > README.md
```

もう一度状態を確認します。

```bash
git status
```

例:

```text
On branch main

No commits yet

Untracked files:
  (use "git add <file>..." to include in what will be committed)
        README.md

nothing added to commit but untracked files present (use "git add" to track)
```

`Untracked files` の下に `README.md` が出ています。  
**未追跡（untracked）** とは、「Git がまだ履歴管理の対象にしていない新しいファイル」という意味です。

次のコミットに入れたいので、ステージへ乗せます。

```bash
git add README.md
```

成功時は通常メッセージが出ません。  
確認のため、もう一度 `git status` を見ます。

```text
On branch main

No commits yet

Changes to be committed:
  (use "git rm --cached <file>..." to unstage)
        new file:   README.md
```

`Changes to be committed` 側に乗っていれば、ステージに入っています。  
これが [ステージ](./concepts) です。

<details>
<summary>`git add .` で全部乗せてもよい？</summary>

練習では便利です。  
ただし実務では、秘密情報や大きなバイナリまで乗せてしまう事故が起きます。  
慣れるまでは「乗せたいファイルを指定する」方が安全です。  
あとで `.gitignore`（無視リスト）も覚えましょう。  
日常操作のページで触れます。

</details>

## コミットする

```bash
git commit -m "最初の README を追加する"
```

例:

```text
[main (root-commit) a1b2c3d] 最初の README を追加する
 1 file changed, 1 insertion(+)
 create mode 100644 README.md
```

読み方のポイント:

- `[main ...]` … `main` ブランチに記録した
- `a1b2c3d` … このコミットの短い ID（環境ごとに違う）
- `1 file changed` … 何ファイル・何行変わったかの要約

- `-m` … メッセージをその場で書くオプション
- メッセージは「何をしたか」が後から分かる文言にします

履歴を見てみましょう。

```bash
git log --oneline
```

例:

```text
a1b2c3d 最初の README を追加する
```

左が短い ID、右がコミットメッセージです。  
1 行にまとまっていれば、最初のコミットは成功です。

## いま起きたことを振り返る

1. `git init` で履歴置き場を用意した
2. ファイルを編集・作成した（作業ツリー）
3. `git add` でステージに乗せた
4. `git commit` で履歴に残した

この 2 → 3 → 4 が、これから毎日くり返す基本形です。  
くわしくは [日常の操作](./daily-commands) へ進みます。

## よくあるつまずき

| 症状 | よくある原因 | まず試すこと |
| --- | --- | --- |
| `Please tell me who you are` | 名前・メール未設定 | 上の `git config --global` を実行 |
| `nothing to commit` | 変更がない / add していない | `git status` で確認 |
| メッセージ入力画面が開いた | `-m` を付けなかった | エディタが開く。保存して閉じるとコミット完了（環境により操作が違う） |

<details>
<summary>コミット画面（エディタ）が開いてしまったとき</summary>

`-m` なしで `git commit` すると、メッセージ入力用のエディタが開くことがあります。  
閉じ方が分からず戸惑いがちです。  
落ち着いて、表示されている使い方（下部のキー案内など）に従って保存・終了してください。  
次回からは `-m "メッセージ"` でこの画面を避けられます。

</details>

## まとめ

- 最初に `user.name` / `user.email` を設定する
- `init` → 編集 → `add` → `commit` で履歴の 1 歩目が残る
- 迷ったら `git status`

次は、変更を重ねるときの定番コマンドです。  
[日常の操作](./daily-commands) へ進みましょう。
