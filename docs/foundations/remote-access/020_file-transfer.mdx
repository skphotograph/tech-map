# ファイルを運ぶ

リモート作業では、「ログインして編集する」以外に、**ファイルそのものを手元とサーバのあいだでコピーする** 場面が頻出します。  
ここでは SCP / SFTP を中心に、FTP の位置づけと、作業全体のチェックリストも整理します。

## このページで分かること

- `scp` でのファイル／ディレクトリコピー
- SFTP の基本操作（実行例つき）
- FTP を避ける理由と、現場で残っているときの注意
- 接続から切断までの実務チェックリスト

## SCP：単発コピーの定番

`scp` は、SSH を使ってファイルやディレクトリをコピーするコマンドです。  
使い勝手は `cp` に近く、接続先だけ `ユーザー@ホスト:パス` になります。

**基本的な使い方:**

1. 手元 → リモートなら `scp ローカルパス ユーザー@ホスト:リモートパス`
2. リモート → 手元なら左右を逆にする
3. ディレクトリごとなら `-r` を付ける
4. 進捗表示を見て、終わったらリモート側で `ls` 確認すると安心

手元 → リモート:

```bash
scp ./notes/app.conf alex@203.0.113.10:/home/alex/app/
```

例（イメージ）:

```text
app.conf                                  100%  128    12.0KB/s   00:00
```

読み方のポイント:

- ファイル名 … 何を送ったか
- `100%` … 転送完了の目安
- 右のサイズと速度 … どれくらい送れたか

リモート側のパスは、相手のファイルシステム上の場所です。

リモート → 手元:

```bash
scp alex@203.0.113.10:/var/log/app/error.log ./
```

ディレクトリごと送るときは `-r` です。

```bash
scp -r ./webroot alex@203.0.113.10:/home/alex/deploy/
```

ポートが 22 以外のとき:

```bash
scp -P 2222 ./notes/app.conf alex@203.0.113.10:/home/alex/app/
```

:::info[`-p` と `-P`]

`scp` ではポート指定が **大文字の `-P`** です。  
`ssh -p`（小文字）と混同しやすいので注意してください。

:::

踏み台経由が必要なときは、`scp` でも ProxyJump を使えます（OpenSSH の版による）。

```bash
scp -o "ProxyJump=alex@bastion.example.com" ./notes/app.conf alex@10.0.0.20:/home/alex/
```

`~/.ssh/config` に `ProxyJump` を書いておけば、別名宛の `scp` でも効くことが多いです。

## SFTP：対話的に運ぶ

SFTP は、SSH 上で動くファイル転送の仕組みです。  
GUI の SFTP クライアントを使う現場も多いですが、コマンドでも入れます。

`sftp` は、SFTP でリモートとファイルをやり取りするコマンドです。

**基本的な使い方:**

1. `sftp ユーザー@ホスト` で入る
2. `ls` / `pwd` でリモート側の場所を確認する
3. `put` でアップロード、`get` でダウンロード
4. 終わったら `bye`（または `exit`）

```bash
sftp alex@203.0.113.10
```

例（セッションのイメージ）:

```text
Connected to 203.0.113.10.
sftp> pwd
Remote working directory: /home/alex
sftp> ls
app  notes
sftp> put notes/app.conf
Uploading notes/app.conf to /home/alex/app.conf
notes/app.conf                                   100%  128    12.0KB/s   00:00
sftp> ls
app  app.conf  notes
sftp> get app.conf app.conf.from-remote
Fetching /home/alex/app.conf to app.conf.from-remote
app.conf                                         100%  128     8.0KB/s   00:00
sftp> bye
```

読み方のポイント:

- `Connected` … SSH と同様、認証が通ってセッションが始まった
- `sftp>` … 対話プロンプト。ここにサブコマンドを打つ
- `put` のあとの `Uploading ... 100%` … 手元 → リモートの転送が完了
- `get` … リモート → 手元。第 2 引数で手元の名前を変えられる
- `bye` のあと手元のシェルに戻る

よく使うサブコマンド:

| コマンド       | 意味                       |
| -------------- | -------------------------- |
| `pwd` / `lpwd` | リモート / 手元の現在地    |
| `ls` / `lls`   | リモート / 手元の一覧      |
| `cd` / `lcd`   | リモート / 手元の移動      |
| `put`          | 手元 → リモート            |
| `get`          | リモート → 手元            |
| `mkdir`        | リモートにディレクトリ作成 |
| `bye`          | 終了                       |

:::tip[使い分け]

- 一発でパスが決まっている … `scp` が速い
- 相手のディレクトリを見ながら選ぶ … SFTP（GUI 含む）が向く

どちらも土台は SSH なので、鍵やユーザー、踏み台の考え方は [SSH](./ssh) と同じです。

:::

## FTP：残っているものとして知る

FTP クライアントの例（環境に入っている場合）:

```bash
ftp 203.0.113.10
```

`ftp` は、FTP でファイル転送するための伝統的なコマンドです。  
ログイン後に `get` / `put` する、という流れ自体は SFTP に似て見えることがあります。

ただし [考え方](./concepts) で触れたとおり、**暗号化されない通信になりやすい** のが大きな問題です。  
パスワードやファイル内容が経路上で見えやすい形態が残っています。

:::warning[FTP を使う前に確認]

- 本当に FTP 以外が不可か
- VPN 内など、経路が保護されている前提か
- FTPS（TLS 付き）や SFTP への移行が検討されていないか

新規の「とりあえず FTP」は避け、チームの標準手段に従ってください。

:::

<details>
<summary>rsync という選択肢（入口）</summary>

`rsync` は、差分を見ながら効率よくコピー・同期するコマンドです。  
SSH 経由で使うことも多く、デプロイやバックアップの定番です。

```bash
rsync -av -e ssh ./webroot/ alex@203.0.113.10:/home/alex/deploy/webroot/
```

強力なので、削除同期（`--delete`）などは十分理解してから使います。  
まずは `scp` / SFTP で「運ぶ」感覚を固めてからで十分です。

</details>

## 転送前の安全チェック

- 宛先パスを間違えていないか（本番ディレクトリへ直接上書きしていないか）
- 秘密情報（鍵、`.env`、認証情報）を不要な場所へ置いていないか
- 転送後の権限は適切か（[権限](../linux/permissions)）
- 大きなファイルは、先にディスク空きを確認（[実務での使い方](../linux/daily-ops)）

:::tip[迷ったらコピー先をホーム配下に]

最初は `/home/自分/...` など、影響の小さい場所へ置き、配置手順が固まってから本番パスへ移す方が安全です。

:::

## 実務チェックリスト（接続から切断まで）

リモート作業を一通りやるときの型です。  
毎回全部を紙に書く必要はありませんが、慣れるまではこの順が崩れにくいです。

1. **接続前**
   - 宛先ホスト・ユーザー・ポート（必要なら踏み台）を確認する
   - VPN や許可が必要なら先に通す
   - 送るファイルに秘密情報が混ざっていないか見る
2. **入る**
   - `ssh`（必要なら `-J` / config の別名）
   - 初回なら指紋を案内どおり確認する
   - 入れなければ `ssh -v` でネットワーク切れか認証切れかを見る
3. **現在地を確認する**
   - `pwd` / `whoami` / `ls`（もうリモート側）
4. **運ぶ（必要なとき）**
   - 単発なら `scp`、対話なら `sftp`
   - 送ったあとリモートで `ls` やサイズを確認する
5. **作業する**
   - 編集・調査は [Linux / Shell](../linux/) の操作
   - 本番パスへの直接書き込みは、手順があるときだけ
6. **抜ける**
   - `exit`（または Ctrl+D）
   - 手元のプロンプトに戻ったことを確認する

:::tip[短く言うと]

確認してから入る → 入ったら現在地 → 運ぶなら控えを残す → 作業 → 抜け漏れなく切断。

:::

## よくあるつまずき

| 症状                            | よくある原因                     | 方向性                                 |
| ------------------------------- | -------------------------------- | -------------------------------------- |
| `Permission denied`             | リモート側の書き込み権限不足     | 宛先ディレクトリの権限・所有者         |
| パスが無い                      | リモート側に親ディレクトリが無い | 先に SSH で `mkdir`                    |
| `scp` のポート指定が効かない    | `-p` と `-P` の取り違え          | `scp` は `-P`                          |
| SFTP で手元のファイルが見えない | 手元側のカレントが違う           | `lpwd` / `lls` / `lcd`                 |
| FTP だけ失敗する                | FW や受動モードの問題            | 可能なら SFTP へ。残りは環境担当と確認 |

## まとめ

- ファイル転送の第一候補は SCP / SFTP（SSH 経由）
- `scp` は単発、`sftp` は対話・GUI 向き
- FTP はレガシー。理由と経路を確認できるとき以外は使わない
- 接続〜切断はチェックリストの型で揃えると事故が減る

これでリモートアクセスの入口は一通りです。  
[章の入口](./) に戻るか、続けてネットワーク基礎・HTTP へ進むと、つながりの全体像が見えやすくなります。
